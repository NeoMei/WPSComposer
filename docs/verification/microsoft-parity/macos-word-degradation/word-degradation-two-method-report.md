# Two-method direct Mac Word degradation slice

2026-09-09. Implementation ready for independent review; native acceptance absent.

## Changes and consumer compatibility

Only `macos_word_degradation.py` and its new focused tests were implemented.
`session.py` was not edited. The exact implementation brief is
`word-degradation-two-method-implementation.md` in this directory.

- Reuses WriterComposer shared display normalization/redaction/wrapping; message
  stays inert. Exact placement equality with `inline` selects inline; other values
  remain block. Safe scalar fallbacks are coerced by the shared baseline.
- UTF-16 display ranges, italic/dark red/light red formatting, 0/3 paragraph
  spacing, keep together/body outline, and a non-splitting single-cell row.
- Returns immutable session-tagged range snapshots with Start/End/Text, or a box
  with Range and native table index. Consumer audit: existing executor/media
  callers ignore these return values; upcoming baseline quality upsert reads
  Range.End. These snapshots expose acknowledged facts, not persistent mutable
  COM references or durable IDs. No edit API accepts the snapshots.
- Committed insertion state changes only after strict success ACK. Malformed
  ACK/transport uncertainty/cancellation retains evidence and quarantines.
- Valid table-failed ACK invokes real recovery checkpoint rollback. Range fallback
  is submitted only after rollback has validated and acknowledged exact preimage.
  Failed/malformed rollback and failed fallback stop the chain. The recovery
  module's own post-rollback state commit occurs after its ACK as designed.
- No quality anchor family or broader business API was added.

transport. They prove pure validation and sequencing, not that Word accepted the
new AppleScript primitives or that native formatting persisted. Table ACK assumes

editable save/PDF/close/reopen also remain unproven.
