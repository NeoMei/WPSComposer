# Office.js Word gap feasibility — bounded supplement

2026-09-09. Research only: current official Microsoft documentation plus existing local contracts/native summaries. Only this report was written. No implementation, install, certificate trust, macro, Office/UI command, or Windows execution was attempted.

**Recommendation:** retain the supplement as a concrete candidate for document-bound attachment, native compressed snapshots, and explicit-range insertion. It does not automatically close the nine missing methods. First prove binding plus non-mutating snapshot; then one middle-range OOXML insertion. These are separate gates from the parent's current AppleScript work and CI.

## Snapshot applicability and its limits

Microsoft documents `getFileAsync(Office.FileType.Compressed)` as a temporary copy of the **current** Word document in DOCX format. The API reference explicitly supports Word on both Windows and Mac. This is a stronger candidate than SaveAs for avoiding path rebinding, and it could avoid the side-effectful AppleScript property enumeration. It is not proof that this installed host preserves unsaved edits, dirty state, selection, layout, fields or read-only/protected-document behavior. [Whole-document guide](https://learn.microsoft.com/en-us/office/dev/add-ins/develop/get-the-whole-document-from-an-add-in-for-powerpoint-or-word), [platform support](https://learn.microsoft.com/en-us/javascript/api/office/office.document?view=common-js#office-office-document-getfileasync-member(1))

Use `File` and `CompressedFile` requirement sets 1.1, then actually call the API. The generic common-set table and getFileAsync table disagree about Word web availability; this proposal is desktop-only and must not infer web support. [Common requirement sets](https://learn.microsoft.com/en-us/javascript/api/requirement-sets/common/office-add-in-requirement-sets)

Desktop slices support up to 4 MiB, but a smaller bounded transfer size is preferable. Retrieve each exact index, validate count/length/total size and a local final hash, and always attempt `closeAsync` on the returned File, including failure/cancellation; Office allows at most two such files in memory. This closes the snapshot handle, not the user's Word document. [File lifecycle](https://learn.microsoft.com/en-us/javascript/api/office/office.file?view=common-js)

A compressed package supplies persistent styles, numbering, sections, relationships, drawings and math for local semantic comparison. It does **not** supply the existing quality DTO's live selection/native offsets, in-memory field-owner registry or page-layout facts. Do not replace that DTO with a ZIP hash: native serialization can normalize XML, and a hash cannot identify allowed insertion deltas. Never restore the entire package over the live document as an unproven rollback. Snapshot export also does not close save/discard/reopen semantics or legacy-format preservation.

## Minimum requirements and runtime gates

Keep a small initial manifest/runtime baseline and feature-specific gates; do not infer support solely from the recorded Office version. Numbered API members below are documented released sets even when a reference page is displayed in preview view. Use the production Office.js CDN; do not depend on BETA members. [Word requirement sets](https://learn.microsoft.com/en-us/javascript/api/requirement-sets/word/word-api-requirement-sets)

- Snapshot/binding probe: WordApi1.1 plus File1.1 and CompressedFile1.1. Read `document.saved` before/after; it is a read-only 1.1 property. [Word.Document](https://learn.microsoft.com/en-us/javascript/api/word/word.document?view=word-js-preview#word-word-document-saved-member)
- Basic picture/table primitives: WordApi1.2 / 1.3. Bookmark lookup and table merging: 1.4; direct field insertion: 1.5. OOXML-only insertion has a lower 1.1 floor but does not bypass field/identity verification requirements.
- Explicit native range `start/end/storyType`: WordApiDesktop1.4, not WordApi1.1. Tracked range objects adjust with surrounding edits but are session objects, not persisted IDs. [Range coordinates/tracking](https://learn.microsoft.com/en-us/javascript/api/word/word.range?view=word-js-preview)
- Optional drawing inventory: Desktop1.2. Complex-script font sizing: Desktop1.3. Microsoft's minimum Mac versions for these desktop sets are respectively 16.94, 16.99.2 and 16.100.4; Windows versions are 2502, 2507 and 2508. Actual `isSetSupported` results and invocation outcomes remain required; not all perpetual/LTSC editions support them. [Build matrix](https://learn.microsoft.com/en-us/javascript/api/requirement-sets/word/word-api-requirement-sets)

Minimum probe sequence, under a separately assigned native lease:

1. Record host/platform/version, requirement flags and method availability; bind two documents (one unsaved), switch focus, duplicate a window, reload/close a pane and reject the old instance. No custom-property or bookmark identity writes merely to attach.
2. Snapshot saved, unsaved-edited and read-only fixtures containing nonempty headers/footers, list styles, fields, images, OMath and tables. Before/after saved flag, path, selection, text and structural facts must match; copies must contain unsaved changes and reopen with native objects intact. Inject a slice failure and prove handle release plus no publication of partial bytes.
3. One exact 12:19 REPLACE-range OOXML table insertion between PREFIX/SUFFIX, then collapsed paragraph and cell cases. Capture inserted-range identity, preserved old content and native object type; serialize, independently compare XML, then actual Undo and explicit discard/save/reopen with an unrelated sentinel.
4. Only after those primitives pass, run the nine frozen per-method contracts and quality failure→verified local restoration→fallback cases. Unknown mutation completion remains quarantined; Office.js batching is not a transaction or rollback proof.

## Small local package needed later — not created now

Proposed task-owned files: `manifest.word.xml`; `taskpane.html`; `taskpane.js` with closed operation handlers and capability reporting; a loopback host/instance registry with generation IDs, pairing and one-command deadlines; a sliced-snapshot collector/validator; owned DOCX/PNG/OMML fixtures; a read-only package/quality comparator; pure bridge/handler tests; and per-platform probe output containing source hashes, capabilities, before/after facts, raw errors and exported copies. Keep these under a new Office.js-specific directory instead of silently reusing WPS JSAPI registration or its engine identity.

For a combined Word object-model probe, the manifest needs ReadWriteDocument even for read-only Word API calls. A common-API-only compressed exporter can use ReadAllDocument. This describes required setup files, not permission changes made here. [Permission model](https://learn.microsoft.com/en-us/office/dev/add-ins/develop/requesting-permissions-for-api-use-in-content-and-task-pane-add-ins)

The official Mac add-in-only-manifest sideload location is `~/Library/Containers/com.microsoft.Word/Data/Documents/wef`; enabling the add-in and any needed server/certificate setup are future controlled acceptance work. No manifest was copied there and no Office restart/trust change occurred. [Mac sideload documentation](https://learn.microsoft.com/en-us/office/dev/add-ins/testing/sideload-an-office-add-in-on-mac)

**Evidence boundary:** documented capability plus a proposed probe, not native-proven Office.js behavior. The existing native blockers remain open until source-bound Mac and Windows acceptance; no currently available remote Windows execution surface is assumed.
