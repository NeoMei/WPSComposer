Independent reviews are scoped implementation checks, not final whole-parity approval.

The follow-up adds 13 more direct Mac Word methods for paragraph styles, headings, code paragraphs, columns, sections, footer PAGE fields and field refresh. The 55 new tests include syntax-only compilation; four independent-review findings were fixed (style-name substitution, inheritance cycles/case aliases, incompatible style types, and a two-column fixture that reset itself before saving). Native execution resumed on September 9; it exposed a Consolas East Asian font-slot rejection and a footer PAGE field being inserted into the main story. Both defects are fixed: final `macos-word-business/resume-03` and `macos-word-business-followup/resume-03` pass 9 and 10 native/artifact checks respectively. Independent review confirmed font slots, exact footer fields, source hashes and three-section header inheritance; the false-positive field validator was then strengthened with 21 pure tests and re-reviewed. Static inventory now finds 35 of the frozen 80 direct Word method names; the [remaining 45 methods](word-direct-remaining.md) are still implementation gaps. Name presence is not a support or native-coverage percentage.

Full suite round 8 passed **3,717 tests with 12 skips** in 186.73 seconds; see `unit-round8.txt`. The skips include opt-in native gates and are not native passes. After all scoped production fixes, round 9 passed **3,731 tests with 12 skips** in 244.25 seconds; see `unit-round9.txt`.

`fixtures/microsoft_parity/macos_powerpoint_size_probe.py` is a guarded hypothesis test for width/orientation swaps. The first native run confirms 720×405 and 405×720 saved/reopened/PDF dimensions, but resizing moved existing shapes (the landscape PDF became blank). `run-02` verifies size-before-content dimensions, exact textbox/rectangle geometry, nonempty PDF and native reopen for both orientations. Production initial-sizing integration and independent review passed. `macos-powerpoint-initial-size/run-05` verifies public creation at 720×405 and 405×720, precise geometry/PDF/native reopen, unchanged source files, rejected existing-content resizing without changes, lower-level recorded-plan generation at 720×405, and default public generation at 960×540. Its fixture/compiler/session/runtime hashes match the reviewed source. Public `generate()` gains no size argument. Existing-content resizing and untested dimension combinations remain open. Unrelated document text is hashed in memory before logging, including timeout diagnostics.
