# Formatted-text and automatic style redefinition — bounded hypothesis

Preparation only; no native lease and no production changes.

Dictionary evidence supplies a plausible, unproven path: text-range `formatted text` is read/write; a Word paragraph style has read/write `automatically update`; `selection of boundWindow` has explicit start/end and style properties. Microsoft documents that a style can be redefined when reapplied to a selection already using it but containing different manual formatting; automatically-update true avoids the redefinition confirmation. This applies to paragraph styles only. There is no separate single-style `update style` command: dictionary `update styles` copies all styles from the attached template and is inappropriate here.

Sources: [Style.AutomaticallyUpdate](https://learn.microsoft.com/en-us/office/vba/api/word.style.automaticallyupdate), [Range.FormattedText](https://learn.microsoft.com/en-us/office/vba/api/word.range.formattedtext); installed Word.sdef SHA256 `7cb51b924cab566320cc3019e92c1516302ae11220a81ae6279f1930c26320e7`.

## Exact candidate dataflow

1. In a fresh owned document, seed a source Heading 1 with mixed Latin/CJK/Arabic text and nondefault font/paragraph appearance. Create one private custom paragraph style, based on Normal, and apply it to a separate temporary owned paragraph. Record source font actual values, native paragraph facts and a source DOCX/XML preimage. The existing scalar-copy approximation must not be counted as complete clone success.
2. Resolve the exact source paragraph's **text excluding its paragraph mark** and the target temporary paragraph's same-length text excluding its mark. Use `set formatted text of targetTextRange to formatted text of sourceTextRange`. Excluding CR is deliberate: Microsoft states paragraph formatting is transferred when a paragraph mark is included; copying an entire Heading 1 paragraph would carry its identity and cannot prove a detached clone. Assert the destination paragraph still uses the private custom style after transfer; fail immediately if it becomes Heading 1 or its linked style.
3. Set `paragraph format of detachedStyle` to `paragraph format of sourceStyle` through the dictionary's writable native object property. This is a separate unproven ParagraphFormat copy mechanism. It must not change the clone's Normal base or source style. Full native paragraph comparison and complete pPr XML equality are required; no list-style reference may be retained as a shortcut.
4. Set `automatically update of detachedStyle` to true **for this new private style only**. Activate only the bound owned window, set its selection to the exact temporary target paragraph, assert that the selection remains bound to the intended paragraph and already uses the clone style, then reapply `style of selection` to that same detachedStyle. Hypothesis: native Word redefinition materializes the transferred manual character formatting into the custom style's complete font definition, including szCs. This is not guaranteed by dictionary presence; may fail or merely clear formatting.
5. Immediately set automatically-update false on the private clone; do not change any application/global/template option. Capture complete 65 font observations and native paragraph facts. Require source style unchanged and destination style Normal-based, distinct and unnumbered. Save DOCX/PDF and compare full clone/source rPr and pPr, retaining szCs and all nested attributes. A visually matching temporary range with missing style-level rPr is a failure.
6. Append a fresh third paragraph using only the detached style and ordinary text insertion, without source-formatted-text copying. Its complete effective appearance must match the clone. This catches formatting that stayed only on the temporary range instead of reaching the style definition.
7. Only after complete style equality passes, temporarily alter two explicit source style scalar properties (font size and paragraph spacing) in a separately acknowledged phase. Verify that both clone style and fresh clone paragraph remain unchanged. Restore the exact two original source values; require full source actual-value and XML preimage equality afterward. This intentional private-source challenge is separate from the requirement that the copy operation itself never mutates source. Any failed restore retains the owned staging and cannot be described as a preserved-source success.
8. Save/reopen and repeat complete font/paragraph/style independence checks; exact owned close before unchanged unsaved-sentinel verification and independent guarded close. Preserve source snapshots, actual values, full XML/PDF and all raw phases. No macro, clipboard copy/paste, global settings or Office.js setup.

## Main uncertainty

FormattedText may preserve only a source style reference instead of materialized manual properties, and same-style reapplication may clear direct formatting instead of redefining the custom style when invoked through AppleEvents. Those are the two actual host questions. The probe must fail closed if destination identity changes, named-style full XML differs, source changes, or later source mutation changes the detached result. No fallback to treating range-only appearance as named-style cloning is valid. If this path fails, the dictionary provides no already-proven complete named-style clone; Office.js remains a separately evaluated supplement.
