## Most directly affected public contract

`MacWordSession.apply_structural_op` accepts `{op: insert, type: table, position: ...}` and emits `make new table at boundDoc` with `text object:insertionRange` (`macos_word_session.py:574-616`). `_position` supports document start/end and before/after/index anchors (`:546-560`); `edit_preflight.py:628-692` validates these positions, dimensions, materialized rows and literal data, without restricting table creation to the end. After submission the method accepts only the generic transport ACK and returns `reinspect_required=True` (`:664-668`), without observing new-table bounds. `document_api.apply_ops` turns this normal return into `ok:True` (`document_api.py:569-575`). Thus the same constructor behavior can silently violate an already-public placement contract for nonterminal insertions. This is a high-confidence impact inference requiring a focused public native reproduction, rather than evidence that every table method is broken.

**Do not conflate insertion and replacement:** structural table insertion constructs a collapsed range at the requested anchor. Inserting before a paragraph must retain that paragraph's text, including any REPLACE marker. The internal semantic primitive instead receives a possibly nonempty `[start,end)` selection and must consume that selected span. The native tests must assert the correct contract for each call path.

## Existing test blind spots

- `test_macos_word_session.py:193-205` exercises only default-position table insertion and checks that the emitted script contains `make new table` plus a reinspect flag. Its fake native transport returns generic success and cannot detect wrong placement.
- `test_macos_word_business_objects.py:33-36,94-114` fabricates a correct count/dimension table ACK; `test_default_table_widths...` also checks emitted strings. These prove command construction and metadata validation, not where Word creates the object.
- `test_macos_word_semantic_table.py:150-170` verifies supplied coordinates and frozen primitive operations but explicitly asserts the old `make ... at boundDoc` spelling. The COM oracle proves desired command semantics, not AppleScript location behavior. A working typed-range constructor should update this assertion only alongside independent native evidence of those unchanged semantics.
- Quality and degradation ACK tests can reject forged positions but do not prove the emitted constructor yields valid positions. Existing end-of-document notice acceptance should remain its own regression evidence.

## Required RED/check sequence if the location experiment succeeds

1. **Public structural RED on the old constructor:** exact owned document with PREFIX, an anchor paragraph, SUFFIX, and a pre-existing later table. Through `apply_structural_op` (and one `document_api.apply_ops`/public edit representative), insert a small unique table at start, before/index paragraph 2, and after its anchor. Verify actual table start/order, unchanged original text, one-table delta and preserved old table; native success must not count if the new table is appended. Include a distinct foreground sentinel to prove bound-document ownership.
2. **Semantic replacement RED:** collapsed middle insertion and nonempty selected-span replacement are separate cases. Require old selected text gone only in replacement, prefix/suffix byte-equivalent, unchanged old table and one new table in the requested slot. Cover UTF-16 coordinates using Chinese/emoji, actual returned object identity, trailing paragraph delta and resulting selection cursor. Saving/reopening must retain order and merge/grid/style semantics. A literal constructor-string test is insufficient.
3. **Postcondition regression:** where new runtime ACKs are introduced for public structural creation, reject native output with correct counts/dimensions but wrong start/end, wrong document binding or wrong preserved prefix/suffix; quarantine/retain unknown mutation instead of reporting `ok:True`. Test malformed/bool coordinates and no further native write after rejection. Do not add automatic arbitrary-middle deletion/rollback merely to make the check pass.
4. **Changed-callsite regression only:** if append constructors are changed, validate empty and nonempty terminal paragraphs, correct separator/last-table target, preceding content and old tables, one merged-table sample, and existing append-notice ACK/native-unit rules. If only the internal primitive or public nonterminal path changes, do not infer an unrelated generation rewrite is required.
5. **Quality boundary retention:** feed a misplaced-table ACK and retain its existing refusal; keep target-position and exact-preimage gates closed. A constructor success is not approval to remove the size/drawing/adjacent-table restrictions or to claim quality native acceptance.
6. **Argument/lifecycle safety:** invalid dimensions/data/anchors remain pre-submission; read-only/expired/stale/quarantined sessions remain blocked. A typed insertion location must use the exact bound document/range and must not rely on the active global selection. Preserve the frozen parent/native lease and source/sentinel evidence discipline for real tests.

The audit identifies the public impact and required acceptance shape; it does not certify a particular AppleScript replacement syntax or claim that the pending location experiment has passed.

## Matrix02 update and immediate containment choices

Root subsequently reports two completed native matrix02 cases with exact owned close and empty inventory: A activates the bound window, resets selection to 12:19, then `make ... at boundDoc` still appends at 62:78; B changes only the `make` location to `diagRange`, producing a table at 20:36 after the REPLACE paragraph while leaving REPLACE intact. Therefore neither activating/reselecting nor replacing the `at` object alone establishes the semantic replacement contract. The current audit does not approve either as a production repair.

Two bounded containment choices exist while a correct range primitive is investigated:

- **Native postcondition/no-false-success check:** record the requested collapsed insertion point and preimage, then verify the returned table's exact slot/order and preserved original content before accepting public structural success. A misplaced table must retain/quarantine the uncertain document and report failure, not publish `ok:True`. This makes errors honest but does not prevent the wrong edit already occurring; it is containment, not full location support. Existing generic `[['ok']]` cannot supply this proof.
- **Temporary preflight rejection:** if nonterminal structural insertion cannot yet be verified, reject those table positions locally in the shared `validate_word_structural` path used by request-wide capability preflight and by the direct session method. An intentionally conservative gate could keep only the explicit default/end path until richer anchors are proven. This avoids knowingly performing a misplaced native mutation, but reduces currently accepted syntax and must be recorded as an outstanding required capability, with a follow-up acceptance matrix—not removed from the baseline or presented as completed parity. A gate only after earlier operations in a multi-op edit would be too late; keep the existing request-wide preflight behavior. No production gate change is made or approved by this audit.

The retained Word dictionary independently confirms `convert to table` takes a `text range` direct parameter, accepts row/column counts and separator/formatting options, and returns a table (`constructor-matrix-01/localWord.sdef:8682`). That makes it a justified next isolated API hypothesis, not proof of exact in-place replacement. Its experiment should separately record exact range consumption, preserved prefix/suffix and old table, delimiter behavior for literal tabs/CR inside intended cell text, CR/table-marker deltas, returned table identity, and selection after the operation. Do not substitute generated plain text or a relocated table and count visual similarity as the frozen semantic-range requirement.

Full34 remains untouched. All nonterminal insertion/replacement requirements remain in scope regardless of the temporary safety choice.
