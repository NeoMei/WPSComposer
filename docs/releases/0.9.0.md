# WPSComposer 0.9.0

Release date: 2026-09-08. Accepted implementation baseline: `313bea4`.

## Changes

Public `generate()` and `convert_to_pdf()` accept keyword-only `engine="wps"`, `"msoffice"` or `"auto"`. WPS remains the default. Auto chooses an installed compatible engine before native work, prefers WPS and keeps that choice through generation, quality checks, conversion and presentation.

The new Microsoft backend drives real desktop Word through COM on Windows and AppleScript on macOS. It supports DOCX/PDF generation and DOC/DOCX-to-PDF conversion. Source files use private conversion copies; task deadlines and verified ownership protect existing user documents. DOCX presentation opens the selected engine.

Native regression fixes cover WPS heading sizes and cover-title outline membership, section page numbering, full TOC refresh, shared multilevel heading counters, Chinese-formal/hybrid numbering and Windows cross-bitness WPS discovery. Chapter insertion/deletion updates descendants and TOC page references through save/reopen. Uncertain cleanup retains task files and explicit recovery diagnostics.

## Scope and installation

Microsoft support covers desktop Word documents. Microsoft Excel, PowerPoint, active-document editing and cloud Office are outside this backend. Existing WPS routes remain available. macOS Word explicitly rejects unsupported advanced operations; see [setup, capabilities and recovery](../../skills/WPSComposer/references/native-word.md).

Clone or update to `v0.9.0`, then run `python3 install.py` (or `python3 install.py --force` for an existing plugin installation). Windows native automation requires `pywin32`; macOS Word requires Automation permission. macOS WPS installation requires Node.js 20+ and npm for its pinned JSAPI runtime.
