# WPSComposer 0.9.1

Release date: 2026-09-19. Baseline: `8cab203d`.

## Changes

Fixes for the native Microsoft Word generation path on macOS, reported against a real feasibility-study conversion (22 pages):

- Heading styles now emit explicit black color on both engines; native Word no longer inherits Word's blue built-in heading defaults.
- Semantic heading numbering accepts decimal level-1 prefixes written as `1.` / `1、` (previously only `1 `), so literal prefixes are stripped instead of rendering double numbers, and a leading unprefixed front-matter section such as `## 文档修订记录` no longer consumes chapter 1.
- Body lists no longer use Word's default list-numbering commands. The document's current list template can be the heading-linked outline template, which flipped trailing list paragraphs onto Heading 1 with chapter numbers. Lists render as body paragraphs with literal prefixes and a 2-character hanging indent, matching the WPS engine.
- Normal and TOC styles pin an explicit simplified Chinese east-asian font, so the default face no longer falls through to viewer-dependent theme substitution.

## Verification

- Full local suite: **2846 passed, 13 platform/native-gated skips**.
- New regression test locks the front-matter/numbering scenario; two macOS compiler contract tests updated to the new list emission; longform_m3 snapshots regenerated with the expected heading-color delta only.
- End-to-end reproduction on the reported document with `engine="msoffice"` before the fix produced all four defects; after the fix the regenerated DOCX was inspected at XML level (style colors, TOC entries, Normal font, tail paragraph styles) and visually page-by-page via native PDF export.
- Delivered file checks: heading 1 color `000000`, Normal eastAsia 宋体, no literal `1. 总论` / `9. 结论与建议` in document text.

## Scope and installation

The WPS engine paths are unchanged except for the shared explicit heading color. Clone or update to `v0.9.1`, then run `python3 install.py` (or `python3 install.py --force` for an existing plugin installation). Note: downstream consumers pinning WPSComposer by commit (e.g. SuperWriter managed dependencies) must repin to `v0.9.1` to pick up these fixes.
