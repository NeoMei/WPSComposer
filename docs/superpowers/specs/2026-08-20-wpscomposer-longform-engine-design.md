# WPSComposer 原生长文档引擎升级设计

## 状态

- 设计日期：2026-08-20
- 目标版本：0.8.0
- 适用范围：Writer DOCX 生成与 WPS 原生 PDF 导出
- 设计状态：用户确认后经实现可行性复审修订
- 参考基准：`1011决策即服务：基于图谱的招投标数据挖掘与AI决策系统构建(2).pdf`

## 背景

WPSComposer 0.7.2 已具备样式驱动的 Writer 生成、原生目录、标题编号、
表格、图片、分节、页码字段、Windows COM 和 macOS JSAPI 生成链，以及
暂存、验证、原子发布和回滚。现有能力足以生成形式正规的报告，但还不能
稳定表达高质量长文档需要的完整语义，包括前置页、分节页码、紧凑目录、
原生题注、图表清单、交叉引用、公式编号、参考文献和布局质量门。

参考 PDF 是一份 43 页 A4 技术研究报告。值得吸收的部分包括：

- 摘要、目录、图表清单、正文和参考文献的完整长文档结构；
- 前置页罗马页码与正文阿拉伯页码重启；
- 正文页统一页眉、页眉线和页脚页码；
- 清晰的章节层级、章节式图表编号和交叉引用；
- 三线表、数学公式、统计图、图谱、代码和系统截图的混合编排；
- 宋体与 Times New Roman 的中英文混排。

不应复制的缺点包括：

- 目录和图表清单条目间距过大；
- 目录末页利用率过低；
- 部分图表标签缩小到难以阅读；
- 个别页面和最终参考文献页留白过多；
- 参考文献中英文间距、换行和对齐不统一；
- 通过静态图片或普通文本模拟本应可编辑的文档语义。

升级目标不是复刻一个固定模板，而是建立可复用于学术报告、技术方案和
技术标的通用高质量长文档引擎。

## 目标

1. 让 `generate()` 的 DOCX/PDF 分支默认使用新的长文档排版行为，PPTX/XLSX
   分支保持现有行为。
2. 以 Markdown 作为稳定公开输入，以内部语义模型承载长文档结构。
3. 在 Windows COM 与 macOS JSAPI 上提供相同的 WPS 原生语义。
4. 使用 WPS 原生字段和对象实现标题、目录、页码、题注、交叉引用和公式。
5. 局部内容或排版错误必须在原位置降级并继续交付有效产物。
6. WPS 引擎不可用、保存失败或产物无效时立即失败，不启用非 WPS 生成器。
7. 即使只请求 DOCX，也必须内部导出临时 PDF 完成分页质量检查。
8. 只交付用户请求的 DOCX 或 PDF，内部 PDF 和暂存文件不得成为伴随产物。

## 非目标

- 不重构 PPTX 或 XLSX 生成。
- 不扩展现有 PDF 编辑器。
- 不自动生成统计图、知识图谱或业务分析数据。
- 不实现完整 CSL、EndNote 或 Zotero 文献管理。
- 不提供现有文档的语义级重新编辑。
- 不实现多人批注、修订模式或文档签名。
- 不新增 python-docx、LibreOffice 或手写 OOXML 备用生成链。
- 不承诺内部 Python 语义模型的第三方兼容性。

## 已确认的产品决策

1. 产品目标是通用高质量长文档引擎，不是样例模板复刻。
2. Windows COM 与 macOS JSAPI 必须同版本达到语义对齐。
3. 对外提供 Markdown 扩展语法；Python 结构化 API 仅供内部流水线使用。
4. 新长文档行为直接成为 `generate()` 的 DOCX/PDF 默认行为。
5. 局部错误采用原位置降级，整体继续交付。
6. 引擎级致命错误立即终止。
7. 本轮只升级 DOCX 与由 WPS 原生导出的 PDF。
8. DOCX 必须经过内部临时 PDF 质量门。
9. 采用语义模型驱动方案，模板只提供样式资产。

## 总体架构

新引擎由六层组成。

### 1. Markdown 表达层

标准 Markdown 继续表达标题、段落、列表、普通表格、代码、图片和链接。
YAML frontmatter 与显式块指令表达摘要、分节、题注、公式、交叉引用和
参考文献。Markdown 不暴露 COM 常量、JSAPI 对象或绝对页面坐标。

### 2. 语义文档模型

`StructuredDocument` 扩展为长文档语义模型。模型描述内容的身份、关系和
版式意图，但不包含平台调用。新增概念包括：

- 文档节与前置页；
- 题注图像与语义表格；
- 题注、稳定 ID 和交叉引用；
- 编号公式；
- 参考文献与引用；
- 页眉、页脚、页码和目录配置；
- 局部降级标记。

### 3. 排版策略层

长文档策略统一决定页面、字体、目录密度、标题、表格、图像、公式、
参考文献、分页和降级标记。现有五个 preset 继续控制颜色、字体气质和
表格视觉变体，但不得破坏编号、字段、分页和质量规则。

### 4. 平台无关生成计划

Writer renderer 将语义模型转换成闭合、可序列化和可验证的操作计划。
生成计划只能包含允许的操作、纯 JSON 参数和逻辑资源 ID，不得包含任意
脚本、平台对象或未经资源策略验证的文件路径。计划协议必须带版本，并在
执行前与平台执行器完成能力握手；版本或能力不匹配时不得开始修改文档。

### 5. 双平台原生执行器

Windows 在 COM WriterComposer 中执行计划，macOS 在 WPS JSAPI add-in 中
执行相同语义操作。平台实现可以不同，但必须生成等价的标题、字段、题注、
页码、交叉引用、公式和降级标记。执行器按白名单区分可恢复的对象级错误
和不可恢复的引擎级错误，并返回结构化 issue 与分页定位快照。

### 6. 内部 PDF 质量门

WPS 保存暂存 DOCX 后，必须临时导出 PDF。共享质量检查器结合 WPS 分页
定位快照分析页面边界、文本和对象位置，并把 PDF 页面问题映射回稳定
`node_id`。可恢复问题最多触发一次确定性重排；之后仍存在的局部问题在
相应位置形成降级标记。引擎级问题立即终止。

完整数据流：

```text
Markdown
  -> 语义模型
  -> 语义验证与规范化
  -> 资源预检；缺失资源转为降级节点
  -> 排版策略
  -> 带版本的闭合生成计划
  -> 执行器能力握手
  -> WPS 原生执行与分页定位快照
  -> 暂存 DOCX
  -> WPS 临时 PDF
  -> PDF 问题映射、质量检查与至多一次重排
  -> 原子发布请求格式
```

## 模块责任边界

### `document_model.py`

保存格式无关的语义数据。不得包含 COM、JSAPI、PDF 坐标或文件发布逻辑。

### `md_parser.py`

解析标准 Markdown、frontmatter 和长文档块指令。不得推断平台能力或直接
选择降级策略。

### 长文档策略模块

新增专用策略模块，保存默认页面、字体、目录、标题、图表、表格、公式、
参考文献和质量规则。避免继续扩大 `reference_styles.py` 的职责。

### `writer_renderer.py`

只负责语义节点到 Writer 操作的编排和对象顺序，不直接调用平台 API。

### `recording_composers.py` 与 `generation_plan.py`

共同构成闭合跨平台协议。新增操作必须先在共享模式中定义和验证，再由
两个平台实现。协议负责版本、阶段顺序、稳定节点 ID、失败策略和返回结果
结构，不把这些规则分散到平台实现中。

### `writer.py`

实现 Windows COM 原生 Writer 原语。不得解析 Markdown 或复制共享策略。

### `macos/wps-jsapi-probe/addin/writer.js`

实现 macOS JSAPI 原生 Writer 原语。操作参数和失败语义必须与共享计划
一致。

### Writer 质量检查模块

新增 Writer 专用质量模块，负责 DOCX 语义快照、PDF 页面指标、问题定位和
重排建议。WPS 执行器生成的 `node_id -> section/page/range/bounds` 分页快照
是问题回写的唯一定位依据，不在正文插入隐藏哨兵文本。现有
`quality_checks.py` 的幻灯片职责保持不变。

## Markdown 公开契约

### 文档配置

```yaml
---
title: 决策即服务
author: 张三
date: 2026-08-20
header: 决策即服务：招投标数据分析
toc: true
figure_index: true
table_index: true
title_page: false
---
```

未提供的可选内容不构成错误。例如未声明 `figure_index`、文档中没有图像，
或未提供摘要，都按普通文档正常生成。

缺省值必须确定且跨平台一致：

- `title`：优先使用 frontmatter；否则使用第一个 H1；仍不存在则为空；
- `title_page: auto`：存在作者或日期时生成，否则不生成；显式布尔值优先；
- `toc: auto`：正文中可收录的 H1-H3 标题达到 3 个时生成，否则不生成；
- `figure_index: false`；
- `table_index: false`；
- `header`：默认使用文档标题；标题为空时不生成正文页眉文字；
- `layout_engine: longform`：仅 DOCX/PDF 生效。

`auto` 只依赖语义模型，不依赖平台、字体测量或首次分页结果，保证同一输入
在两个平台选择相同的文档结构。

### 题注图像

```markdown
:::figure {#fig:supplier-network caption="供应商网络知识图谱" width="full" orientation="portrait" kind="diagram"}
![[供应商网络.png]]
:::
```

`id` 在整个文档内唯一。`caption` 是可见题注文本。`width` 使用语义值，
首版支持 `auto`、`column`、`full` 和带 `pt` 后缀的明确点值，例如
`360pt`。页面方向只能通过显式 `orientation="landscape"` 请求，不能根据
图片比例自动改变。`kind` 支持 `auto`、`photo`、`scan`、`screenshot` 和
`diagram`，用于选择质量规则；`auto` 不确定时按通用 DPI warning 处理，
不得擅自判定标签不可读。

首版并排图使用同一个 figure 块表达，最多两张图片：

```markdown
:::figure {#fig:model-compare caption="模型结果对比" layout="columns" columns="2"}
![[模型A.png]]
![[模型B.png]]
:::
```

`layout` 首版只支持 `stack` 和 `columns`；`columns` 只允许两张图片。整个
组合共享一个原生题注和编号。更多图片、独立子题注和任意网格不进入 0.8.0。

### 语义表格

```markdown
:::table {#tab:node-properties caption="节点属性表" style="three-line" orientation="portrait"}
| 节点名称 | 属性名称 | 具体名称 |
|---|---|---|
| project | itemNumber | 项目编号 |
:::
```

首版表格样式支持 `three-line` 和 `grid`。未指定样式时由 preset 选择：
academic 默认三线表，business、consultant、tech 和 proposal 默认克制网格。
`orientation` 支持 `portrait` 和 `landscape`。`merges` 使用以分号分隔的 A1
范围，例如 `A1:B1;A2:A3`；被覆盖单元格必须为空，冲突、越界或非矩形合并
在语义验证阶段形成原位置降级节点。未声明 `merges` 时按普通矩形表生成。

### 编号公式

```markdown
:::equation {#eq:common-neighbors}
CN(x,y)=|N(x)\cap N(y)|
:::
```

公式 ID 可被交叉引用。公式内容必须使用 Office Math 或 WPS 原生公式对象；
无边框表格只允许作为“公式居中、编号右对齐”的布局容器，不能替代数学
对象。Unicode 文本或图片只能作为运行期降级，不能计入原生能力通过。

### 交叉引用

```markdown
供应商关系如 {{ref:fig:supplier-network}} 所示，
计算方式见 {{ref:eq:common-neighbors}}。
```

引用显示文本由目标类型和当前编号生成。未解析引用在原位置显示可读的
降级标记，不静默删除。

### 参考文献

```markdown
研究已经证明该方法有效 {{cite:chen2025}}。

:::bibliography
- id: chen2025
  text: 陈延超. 数字技术在工程建设招投标中创新应用研究[J]. 中国招标, 2025.
:::
```

首版只提供稳定 ID、引用序号、可读文献文本和统一样式，不实现 CSL 格式
引擎或外部文献管理器同步。

### 解析失败规则

- 不存在可选块时正常生成。
- 块已声明但资源不可用时保留语义节点，并在资源预检阶段规范化为降级节点。
- 未解析交叉引用显示“引用目标未解析”。
- 重复 ID 以第一次定义为目标；后续对象取消引用能力并显示冲突标记。
- 未识别块保留原始文本并显示“未支持的排版指令”。
- 解析器不得静默丢失用户内容。

## 内部语义模型

内部模型至少需要表达以下字段。

### 文档和分节

- 文档标题、作者、日期、摘要、关键词；
- 是否生成标题页；
- 前置页、正文和参考文献节；
- 页面角色，包括标题页、摘要、目录、图表清单、正文、章节首页和参考文献；
- 每节的页码格式、起始值、页眉、页脚和链接到前节策略；
- 是否包含正文目录、图目录和表目录。

### 题注对象

- 稳定 ID；
- 对象种类 `figure` 或 `table`；
- 图像资源列表、排列方式、表格合并范围和显式页面方向；
- 资源状态 `ready`、`missing`、`invalid` 或 `unsupported`；
- 题注正文；
- 章节式编号策略；
- 与对象的同页约束；
- 目录收录策略。

### 公式对象

- 稳定 ID；
- 原始数学表达式；
- 编号策略；
- 对齐方式；
- 原生渲染失败时的简化表示。

### 引用和参考文献

- 目标 ID；
- 引用种类；
- 显示格式；
- 文献 ID 和可见文本；
- 文献顺序和悬挂缩进规则。

### 降级问题

内部 issue 使用稳定结构：

```text
code
severity
node_id
stage
message
fallback
recoverable
page
```

`page` 在分页前可以为空，最终执行后由分页定位快照补充。`message` 不得包含
绝对路径、环境变量、token、密钥或调用栈。

用户显式声明的图、表、公式和引用 ID 在语义模型中原样保留。普通标题、
段落和列表项使用规范化文档遍历顺序生成内部 ID，例如 `para:2:17`；同一份
规范化输入必须得到相同 ID。第二次重排和 notice-only patch 必须复用首次
分配的 ID，不得根据新页码重新编号。

## 默认排版规范

### 页面

- A4 纵向；
- 左边距 30mm；
- 右边距 25mm；
- 上边距 25.4mm；
- 下边距 25.4mm；
- 普通图片不得触发自动横向分节；
- 横向页面必须由语义节点显式请求。

### 正文

- 默认中文宋体 12pt；
- 默认英文和数字 Times New Roman 12pt；
- 两端对齐；
- 首行缩进 2 字符；
- 1.5 倍行距；
- 段前段后 0；
- preset 可以改变字体气质，但必须维持正文可读性和页面密度。

### 标题

- 一级标题黑体 16pt、左对齐；
- 二级标题黑体 15pt、左对齐；
- 三级标题黑体 14pt、左对齐；
- 四级标题黑体 12pt、左对齐；
- 标题与后续至少两行正文保持同页；
- 标题编号必须使用 WPS 原生列表或标题语义；
- 目录只收录配置允许的标题级别。

### 前置页与页码

- 标题页由 `title_page` 控制；
- 摘要、目录和图表清单使用罗马数字页码；
- 正文在新节中从阿拉伯数字 1 重新开始；
- 前置页默认不显示正文页眉；
- 正文页眉居中，并使用段落下边框形成页眉线；
- 页码在页脚居中显示，不强制添加 “Page” 前缀。

### 目录

- TOC 1：11pt、单倍行距、段前 3pt、段后 0；
- TOC 2/3：10.5pt、单倍行距、段前段后 0；
- 唯一一次紧凑重排的下限为 TOC 1 10.5pt、TOC 2/3 10pt、全部段前段后 0；
- 使用缩进表达层级，不插入空段落；
- 使用点引导线和右对齐页码；
- 图表清单使用相同紧凑规则；
- 末页利用率规则只适用于占两页以上的目录或图表清单；
- 末页利用率低于 35%，且在不低于上述最小字号和间距的前提下可以回流到
  前页时，触发一次紧凑样式重排；
- 重排后自然留下的稀疏末页仅记录信息性 warning，不插入文档内降级框、
  不插入空白页，也不删除真实目录项；
- 单页短目录不执行 35% 利用率检查。

### 图片和图表

- 图片居中并保持比例；
- 默认不超过正文宽度；
- 图题在图下方并与图片保持同页；
- 支持上下排列和明确的并排组合；
- 检查最终有效 DPI 和可读文字尺寸；照片或扫描件的有效 DPI 低于 150
  记录 warning；
- 图片无法解码或有效 DPI 低于 96 时，记录可恢复问题并在原位置加入降级
  标记；
- UI 截图和线条图不得只因低于 150 DPI 自动加入可见标记，仍须根据最终
  尺寸和文字可读性判断；
- 标签字号只有在矢量源、已声明资源元数据或可靠文字边界可用时才能自动
  检查；最终估算低于 8pt 时记录可恢复问题，否则留给人工视觉验收；
- 不负责生成图表内容，只负责原生编排现有资源。

### 表格

- 表题在表格上方；
- academic 默认三线表；
- 其他 preset 可以使用克制网格；
- 支持合并单元格、重复表头、列宽约束和单元格零缩进；
- 默认禁止表格行跨页拆分；
- 表题与至少第一行表格保持同页；
- 表内文字使用直接左、中、右对齐，不继承正文首行缩进。

### 公式

- 公式内容必须优先使用 WPS 原生数学对象；
- 公式居中，编号右对齐；
- 公式和编号保持同页；
- 编号和交叉引用可在字段更新后自动刷新；
- 无边框表格可以作为对齐容器，但不属于数学对象替代品；
- 原生公式运行时失败时降级为可读数学文本或图片并显示提示。

### 参考文献

- 使用统一悬挂缩进；
- 默认左对齐，避免中英文间距被两端拉伸；
- 引用序号风格由文档配置统一决定；
- 文献条目不得被空段落人为拉开；
- 中英文文献使用一致的段落间距和换行规则。

## 跨平台生成计划

长文档 Writer 使用 generation protocol v2。计划信封固定为：

```json
{
  "protocolVersion": 2,
  "semanticVersion": "longform-1",
  "component": "writer",
  "operations": [
    {
      "op": "writer.add_captioned_figure",
      "nodeId": "fig:supplier-network",
      "args": {
        "imageIds": ["image-1"],
        "caption": "供应商网络知识图谱",
        "layout": "stack"
      },
      "failurePolicy": {
        "mode": "degrade",
        "recoverableCodes": ["IMAGE_INSERT_FAILED"],
        "fallback": "notice"
      }
    }
  ]
}
```

`failurePolicy` 只允许 `fail` 或 `degrade`。`degrade` 必须同时声明允许恢复的
稳定错误码和确定性 fallback；未列入白名单的错误一律向上抛出。配置、保存、
字段最终刷新、产物验证和发布类操作只能使用 `fail`。

共享计划新增以下语义操作：

- `writer.configure_front_matter`
- `writer.configure_section`
- `writer.configure_toc_styles`
- `writer.add_captioned_figure`
- `writer.add_semantic_table`
- `writer.add_equation`
- `writer.add_cross_reference`
- `writer.insert_figure_index`
- `writer.insert_table_index`
- `writer.add_bibliography`
- `writer.add_degradation_notice`
- `writer.finalize_fields`

`writer.add_captioned_figure` 同时承载单图和首版最多两图的组合；是否并排由
`layout` 和 `columns` 参数决定，不为同一语义另建平台专用操作。

每个操作必须具备：

- 明确的必需字段和可选字段；
- 纯 JSON 参数；
- 严格未知字段拒绝；
- 大小、数量和嵌套深度边界；
- 稳定错误码；
- Windows 和 macOS 等价测试。

计划状态机固定为：

```text
reset
  -> configure document/front matter/styles/sections
  -> render content nodes
  -> insert indexes and bibliography
  -> finalize_fields exactly once
```

- `reset` 必须唯一且位于首位；
- 每个语义内容节点 ID 必须在计划中恰好出现一次；复合操作使用顶层
  `nodeId`，批量普通段落允许使用 `args.segments[]` 记录各子节点的
  `nodeId`、字符起点和长度；
- 交叉引用目标必须在语义验证阶段已解析为稳定 `nodeId`；
- `finalize_fields` 必须唯一且位于最后；
- 阶段越界、重复终结或终结后追加内容属于计划无效，不得启动 WPS。

批量段落只是一项性能传输优化，不能丢失子节点定位。执行器必须把每个
segment 还原为独立 WPS 段落范围；第二次生成可以改变批次边界，但不能改变
语义节点 ID。

### 执行前能力握手

Python 主机在任何 WPS 文档变更之前读取执行器的：

- `protocolVersion`；
- `semanticVersion`；
- 支持的操作目录及其 schema 哈希；
- 原生能力位，包括多级编号、分节页码、TOC 样式、题注、交叉引用、公式
  和分页定位快照。

任一必需值不匹配时抛出 `PROTOCOL_VERSION_MISMATCH` 或
`EXECUTOR_CAPABILITY_MISSING`，不执行 `reset`，也不自动切换 legacy。插件
安装和升级必须把 Python 包、macOS add-in 与能力清单作为一个版本单元。
schema 哈希使用按键排序、无多余空白的 UTF-8 JSON 规范化结果计算 SHA-256，
两个平台不得各自维护不可比较的哈希算法。

### 资源预检与运行期恢复

- 语义规范化阶段先验证资源存在性、类型、大小和可解码性；
- 缺失、类型不支持或预检已确认损坏的资源不进入 `GenerationResource`，而
  直接在原节点生成 `writer.add_degradation_notice`；
- 通过预检但在 WPS 插入时失败的资源，由复合操作按白名单错误码执行一次
  fallback 并继续；
- 可恢复复合操作开始前必须记录插入范围和相关对象计数；失败后先删除该操作
  已产生的局部范围和对象，再插入 fallback；局部恢复验证失败立即升级为
  `LOCAL_MUTATION_ROLLBACK_FAILED` 致命错误；
- `writer.add_degradation_notice` 的内部 fallback 固定为“样式提示框 -> 普通
  带错误码段落”；连普通段落都无法写入时视为 Writer 引擎不可用并终止；
- 平台执行器不得捕获所有异常后继续；未知异常、引擎异常和保存异常必须
  终止。

### 执行结果与分页定位

平台执行器内部返回：

```text
ExecutionOutcome
  staged_artifact
  issues[]
  pagination_map[node_id] -> section, page, range, bounds
  capability_snapshot
```

分页定位必须由 WPS 原生范围、书签或对象锚点产生，并在保存、字段刷新后
重新读取。不允许通过可见文本、隐藏正文哨兵或 PDF 文本猜测 `node_id`。
`range` 对文本节点必需，`bounds` 对图、表和公式等视觉对象必需；不适用的
字段可以为空。一次重排后必须重新生成最终 `pagination_map`，旧映射不得
复用。

## WPS 原生语义原则

- 标题、目录、页码、题注、交叉引用和公式优先使用 WPS 原生对象或字段。
- 平台 API 可以不同，最终语义和可编辑行为必须一致。
- 不要求 DOCX 字节一致，要求语义快照和 PDF 视觉结果一致。
- 新默认引擎不得依赖新增的 OOXML 变更或后处理；只读解析 OOXML 用于结构
  验证和语义快照是允许的。
- 现有 `numbering_native.py` 在迁移期只服务旧链路。
- 新默认链路通过 WPS 原生列表和标题样式实现编号。
- 旧编号后处理只有在新链路跨平台验收通过后才从默认路径移除。
- 标题和 TOC 样式必须通过内置样式 ID、枚举或经探针验证的稳定标识访问，
  不得只依赖英文或中文显示名称。
- 外部语义 ID 必须映射为合法、确定且无冲突的内部书签名；用户输入不得
  直接成为 WPS 书签或字段代码。

内部书签名固定为 `wpsc_<kind>_<24位SHA256>`，其中 `kind` 只能是受控短码
`fig`、`tab`、`eq`、`ref`、`head` 或 `para`。完整外部 ID 与书签的映射保留
在内部结果中；哈希碰撞按规范化文档顺序追加确定性两位后缀。书签名必须
保持 ASCII 且不超过 40 个字符。

“WPS 原生等价结构”是指由 WPS API 创建、可在 WPS 中继续编辑，并且在
保存、重新打开和字段刷新后仍保持显示内容、更新行为和引用目标的对象或
字段组合。仅视觉相似的静态文本、图片或手写 OOXML 不属于等价结构。
公式布局使用的无边框表格可以是等价布局结构，但表格中的公式内容仍必须
是 Office Math 或 WPS 原生公式对象，才算原生公式能力通过。

## macOS 原生能力可行性门

正式实现前必须在真实 macOS WPS 中验证：

1. generation protocol v2 能力握手和版本拒绝；
2. H1-H4 原生关联多级编号，插入、移动、删除、重开后可自动重编号；
3. 分节页码格式和重新起始编号；
4. TOC 1/2/3 样式修改，且不依赖本地化显示名称；
5. `SEQ` 题注字段；
6. 图目录和表目录；
7. 交叉引用字段和安全书签映射；
8. Office Math 或 WPS 原生公式对象，以及无边框布局容器；
9. `node_id -> page/range/bounds` 分页定位快照；
10. 可恢复复合操作的局部清理、fallback 插入和后续操作继续执行。

每项都必须验证保存、关闭、重新打开、字段刷新后的结果。不得转为静态
OOXML 拼补。无法形成跨平台等价语义的能力不得进入 0.8.0。M0 是明确的
go/no-go 门；M0 未全部通过前不得开始 M1 正式实现。

## 错误与降级模型

### 正常缺省

文档没有图、表、公式、目录或参考文献时，直接按实际内容排版，不产生
提示或 warning。

### 可恢复局部问题

以下问题必须继续生成：

- 已声明图片不存在、损坏或插入失败；
- 公式对象创建失败；
- 表格无法按请求样式排版；
- 引用目标不存在或 ID 冲突；
- 某项高级格式在运行时不可用；
- 图片分辨率或标签尺寸低于质量要求。

处理顺序固定为：

1. 语义或资源预检可以提前确认的问题，直接把原节点规范化为
   `DegradationNotice`；
2. 运行期问题先尝试原生排版；
3. 仅对白名单错误执行一次确定性的简化排版；
4. 简化仍失败时，在同一 `node_id` 位置插入 `DegradationNotice`；
5. 继续后续内容，并将 issue 加入内部 `GenerationOutcome`。

降级标记采用专业的浅黄色或浅灰色提示框，包含稳定错误码、对象名称、
可读原因和实际降级方式。

信息性 warning 不自动污染文档正文。只有内容缺失、对象不可读、引用不可
解析或排版问题会导致用户误解时，才插入可见 `DegradationNotice`。无法在
PDF 检测后直接修改原产物；必须更新语义节点并执行唯一一次重排。

### 引擎级致命问题

以下情况立即终止：

- WPS 未安装、无法启动或 COM/JSAPI 不可用；
- generation protocol 或执行器能力不匹配；
- WPS 保存失败；
- 注册恢复失败；
- DOCX 或 PDF 结构无效；
- 内部 PDF 无法导出；
- 必需的 PDF 分析组件不可用；
- 原子发布或回滚失败。

致命错误不得启动非 WPS 备用生成器，也不得把不完整文件伪装为成功产物。

## 返回与交付契约

- 公开 `generate()` 继续返回绝对产物路径。
- 内部流水线使用非公开 `_generate_outcome()`，返回
  `GenerationOutcome(path, degraded, issues)`；不承诺第三方兼容。
- `degraded` 问题既进入结构化 issue 列表，也在文档相应位置可见；warning
  和 info 只进入内部结果，不自动写入正文。
- 普通用户不额外收到诊断 JSON。
- 只发布请求的 DOCX 或 PDF。
- 内部 PDF、暂存 DOCX 和资源副本在成功后删除。
- 失败恢复所需的唯一副本按现有原子发布约定保留并报告。

## 质量门

### 生成顺序

1. Markdown 语义验证；
2. 资源预检，并把已知资源问题规范化为降级节点；
3. generation protocol v2 计划闭合验证；
4. 执行器版本和能力握手；
5. WPS 生成暂存 DOCX，并返回 issue 与分页定位快照；
6. 验证标题、字段、题注、引用、书签和媒体关系；
7. WPS 临时导出 PDF；
8. 执行页面角色感知的 PDF 质量检查，并映射到 `node_id`；
9. 只有可确定修复的问题才触发唯一一次重排；
10. 重排后重新生成分页定位快照，并执行最终 PDF 质量检查；
11. 最终检查仍存在的 `degraded` 问题只允许执行一次原位置 notice patch，
    随后保存并重新导出 PDF；不得再次重排正文；
12. 对 notice patch 后的 DOCX/PDF 执行结构、页面边界和标记存在性验证；
    新增视觉偏差只记录到同一节点 issue，不再进入循环；
13. 原子发布请求格式；请求 PDF 时复用最终已验收 PDF，不重复导出；
14. 删除内部证据和暂存文件。

### 确定性检查

- 非预期空白页；
- 页面内容超出正文区域；
- 页眉、页脚、页码格式和序列；
- 标题位于页尾且后续不足两行；
- 图题、表题与对象分离；
- 图片超宽或有效 DPI 过低；
- 表格超宽、表头未重复或行被拆分；
- 目录字号、行距、段间距和末页利用率；
- 题注断号、重复号或交叉引用未解析；
- 参考文献悬挂缩进和异常字符间距；
- 最后一页利用率过低。

质量规则必须识别标题页、摘要、目录、章节首页、正文和参考文献等页面角色。
标题页、显式章节首页和用户显式分页不参与普通正文利用率判断。最后一页
利用率过低默认是 warning，不得删除真实内容。

严重度固定为：

- `fatal`：引擎、协议、保存、结构验证、PDF 导出或发布失败；
- `degraded`：内容对象缺失、不可读、未解析，或一次重排后仍可能误导用户的
  局部排版问题；
- `warning`：可读且不影响语义的质量偏差；
- `info`：自然稀疏页面等无需修复的观察项。

非预期空白页、对象溢出和题注分离先执行一次确定性修复。修复后仍存在时，
只要 DOCX/PDF 结构有效，就按可恢复问题继续输出，并在对应节点或最近的前置
语义节点加入降级说明；不得把视觉问题擅自升级为引擎级致命错误。

### 确定性重排矩阵

- TOC 稀疏溢页：只调整 TOC 1/2/3 样式到已定义最小值；
- 图片超宽：按正文宽度等比缩小，不自动创建横向节；
- 图片过低：保持可读尺寸并加入提示，不继续缩小掩盖问题；
- 表格超宽：按列宽策略压缩一次；仍超宽则使用节点显式横向节或降级标记；
- 标题孤行：应用 `keep_with_next` 和段落分页规则；
- 题注分离：把对象与题注放入同一原生布局容器或应用保持同页规则。

矩阵之外的问题不允许通过启发式反复调整。每份文档最多执行两次完整 WPS
生成、一次 notice-only patch 和三次 PDF 导出。notice-only patch 只允许在
已映射 `node_id` 处插入提示，不得调整正文样式、对象尺寸或分页策略。

### 人工视觉检查

自动测试不能替代真实 WPS 和 PDF 视觉检查。每个里程碑至少检查代表性的
摘要、目录、正文、图、表、公式、代码、降级标记和参考文献页面。

### 依赖与性能边界

- `pypdf>=4` 和 `pdfplumber>=0.11` 从可选 PDF 编辑依赖提升为 DOCX/PDF
  长文档质量门的核心运行依赖；`reportlab` 仍只服务 PDF 编辑功能；
- 缺失必需分析组件时必须在启动 WPS 前失败；
- 公开 `timeout` 覆盖资源预检、两次以内完整生成、一次 notice-only patch、
  三次以内 PDF 导出、验证和发布的完整生命周期，默认仍为 600 秒；
- warning 或 info 不触发第二次生成；只有重排矩阵中的可确定问题才触发；
- 50-100 页验收夹具必须在 Windows 和 macOS 的记录基准机器上于 600 秒内
  完成，验收记录同时保存硬件、WPS 版本、页数、操作数和各阶段耗时；
- 超时后必须恢复 WPS 注册和 ScreenUpdating，清理暂存文件，并且不得发布
  部分产物。

## 里程碑

### M0：macOS 原生能力探针

验证协议握手、原生关联多级编号、分节页码、TOC 样式、题注、图表目录、
交叉引用、原生公式内容和分页定位快照。产出能力矩阵、真实 DOCX/PDF 和
截图证据，不进入正式 API。

通过标准：每项 0.8.0 能力在 Windows 与 macOS 都有 WPS 原生实现路径，
并通过保存、关闭、重开和字段刷新。任一项失败即暂停 0.8.0 长文档实现，
不得进入 M1。

### M1：长文档语义核心

实现 Markdown 扩展、明确缺省值、语义模型、资源预检、ID/引用解析、书签
安全映射、排版策略和 generation protocol v2 闭合计划。使用 recording
composer 验证，不启动真实 WPS。

通过标准：同一输入稳定生成相同语义计划；缺省内容不报错；声明资源失败
产生降级节点；计划阶段顺序、节点唯一性和失败策略均能在启动 WPS 前验证。

### M2：页面骨架与目录

实现前置页、分节页码、页眉页脚、紧凑目录、标题层级和正文样式。

通过标准：两个平台真实生成的罗马页码、正文重启、页眉和目录密度正确，
没有意外空白页，并能为标题、目录项和正文节点返回稳定分页定位。

### M3：图、表与交叉引用

实现原生题注、章节式编号、图表清单、三线表、图片策略和交叉引用。

通过标准：移动、插入或删除图表后，WPS 更新字段即可重编号；图题和表题
不与对象分离。

### M4：公式、参考文献与降级系统

实现公式编号、公式引用、参考文献样式、引用序号、执行器白名单恢复、局部
降级和文档内提示。

通过标准：所有局部故障都生成有效产物；所有引擎级故障立即终止。

### M5：PDF 质量门与默认迁移

实现内部 PDF、页面角色感知检查、问题到节点映射、一次重排、核心 PDF
分析依赖、性能门、DOCX/PDF 默认行为切换、文档和发布说明。

通过标准：所有真实验收夹具在两个平台通过；DOCX/PDF 的 `generate()` 默认
使用新引擎；PPTX/XLSX 生成计划快照保持不变。

## 验收夹具

至少维护五类真实夹具：

1. 样例风格的密集学术报告；
2. 含宽图、长表和多章节的技术方案；
3. 含混合原生编号的技术标；
4. 故意缺图、引用错误和公式失败的降级文档；
5. 不带 frontmatter 的短普通 Markdown，用于验证 `auto` 缺省行为。

每份夹具在 Windows 和 macOS 上验证：

- DOCX 原生字段和语义快照；
- WPS 打开并刷新字段后的结果；
- WPS 导出 PDF 的页面数量和页面边界；
- 页眉、页脚和页码序列；
- 目录密度、孤立标题和空白页；
- 图片 DPI、题注位置和表格跨页；
- PDF 问题与稳定 `node_id` 的映射；
- 两个平台语义结果一致；
- 代表性页面人工截图检查。

另将第 2 类夹具扩展为 50-100 页性能版本，验证阶段耗时和 600 秒总预算；
短普通 Markdown 不承担长文档性能指标。

另外维护协议不匹配、能力缺失、PDF 分析依赖缺失和超时恢复测试；这些是
失败场景，不生成公开验收文档。

## 兼容性和迁移

- 普通 Markdown 继续可用。
- `generate()` 签名和路径返回值保持兼容。
- 只有 DOCX/PDF 的默认视觉和分页行为升级为新引擎。
- PPTX/XLSX renderer、操作协议和生成计划快照保持现有行为。
- Markdown 扩展成为稳定公共契约。
- 内部 Python 模型不承诺第三方兼容。
- 提供 `layout_engine: legacy` 迁移开关；它被明确标记为 deprecated，不属于
  稳定长文档语法契约，只用于历史 DOCX/PDF 应急且不接受新能力。
- legacy 在整个 0.8.x 保留，不早于 1.0 移除；移除必须通过主版本迁移说明。
- stale add-in 或协议不匹配属于致命错误，不得被 legacy 自动兜底；只有用户
  在输入中显式声明 legacy 才进入旧链路。

## 版本与发布门

目标版本为 0.8.0。以下条件必须全部满足：

1. M0-M5 全部完成；
2. Windows 与 macOS 使用相同语义版本；
3. 全部平台无关测试通过；
4. Windows 和 macOS 真实 WPS 验收通过；
5. 五类验收夹具全部通过结构与 PDF 质量门；
6. README、SKILL、API 参考和长文档语法文档同步；
7. 插件清单和 Python 包版本一致；
8. Python 主机、Windows 执行器与 macOS add-in 的 protocol v2 版本和能力
   清单一致；
9. 默认新引擎和 legacy 逃生路径分别通过验收；
10. PDF 分析核心依赖在全新安装环境可用；
11. 50-100 页性能夹具在两个基准平台满足 600 秒预算；
12. PPTX/XLSX 生成计划回归快照无变化；
13. 未跟踪的 `uv.lock` 和客户文档不进入提交或发布包。

任一平台未通过，不得宣称 0.8.0 长文档能力完成，也不得只发布另一平台。

## 风险与缓解

### macOS WPS API 缺失

缓解：M0 作为 go/no-go 门先行；允许 WPS 原生等价结构，不允许 OOXML
拼补。无等价能力则不进入 M1，也不进入 0.8.0。

### 主机与 add-in 协议漂移

缓解：执行前比较 protocol version、semantic version、操作 schema 哈希和
必需能力位；不匹配时在 WPS 修改文档前失败；安装器按一个版本单元更新
Python 包和 add-in。

### 跨平台字段刷新差异

缓解：比较语义快照和 WPS 导出 PDF，不比较 DOCX 字节；在两个平台分别
刷新字段并记录结果。

### 质量门误报

缓解：区分页面角色、fatal、degraded、warning 和 info；重排最多一次；单页
目录不检查 35% 阈值；最后一页低利用率不自动删减内容。

### PDF 分析依赖或性能成本

缓解：把必需分析库提升为核心依赖并在 WPS 启动前检查；warning 不触发
重排；最多两次完整生成、一次 notice-only patch 和三次导出；用 50-100 页
真实夹具记录分阶段耗时。

### 局部降级污染正式交付

缓解：标记使用专业样式、稳定错误码和最少必要信息；用户可定位并替换问题
资源；不以空白或静默丢失掩盖失败。

### 默认行为升级影响历史文档

缓解：0.8.0 发布说明明确行为变化；提供一个过渡版本的 legacy 开关；维护
旧输入与新引擎的回归夹具。

### 里程碑范围过大

缓解：M0-M5 各自产生独立、可测试交付物；实施阶段为每个里程碑编写独立
计划和审查门，不使用单一大提交完成全部工作。
