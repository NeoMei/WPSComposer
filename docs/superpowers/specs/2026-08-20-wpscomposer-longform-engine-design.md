# WPSComposer 原生长文档引擎升级设计

## 状态

- 设计日期：2026-08-20
- 目标版本：0.8.0
- 适用范围：Writer DOCX 生成与 WPS 原生 PDF 导出
- 设计状态：用户逐节确认
- 参考基准：`1011决策即服务：基于图谱的招投标数据挖掘与AI决策系统构建(2).pdf`

## 背景

WPSComposer 0.7.2 已具备样式驱动的 Writer 生成、原生目录、标题编号、
表格、图片、分节、页码字段、Windows COM 和 macOS JSAPI 生成链，以及
暂存、验证、原子发布和回滚。现有能力足以生成形式正规的报告，但还不能
稳定表达高质量长文档需要的完整语义，包括前置页、分节页码、紧凑目录、
原生题注、图表清单、交叉引用、公式编号、参考文献和布局质量门。

参考 PDF 是一份 43 页 A4 技术研究报告。值得吸收的部分包括：

- 摘要、目录、图表清单、正文和参考文献的完整长文档结构；
- 前置页罗马页码与正文阿拉伯页码重启；
- 正文页统一页眉、页眉线和页脚页码；
- 清晰的章节层级、章节式图表编号和交叉引用；
- 三线表、数学公式、统计图、图谱、代码和系统截图的混合编排；
- 宋体与 Times New Roman 的中英文混排。

不应复制的缺点包括：

- 目录和图表清单条目间距过大；
- 目录末页利用率过低；
- 部分图表标签缩小到难以阅读；
- 个别页面和最终参考文献页留白过多；
- 参考文献中英文间距、换行和对齐不统一；
- 通过静态图片或普通文本模拟本应可编辑的文档语义。

升级目标不是复刻一个固定模板，而是建立可复用于学术报告、技术方案和
技术标的通用高质量长文档引擎。

## 目标

1. 让 `generate()` 默认使用新的长文档排版行为。
2. 以 Markdown 作为稳定公开输入，以内部语义模型承载长文档结构。
3. 在 Windows COM 与 macOS JSAPI 上提供相同的 WPS 原生语义。
4. 使用 WPS 原生字段和对象实现标题、目录、页码、题注、交叉引用和公式。
5. 局部内容或排版错误必须在原位置降级并继续交付有效产物。
6. WPS 引擎不可用、保存失败或产物无效时立即失败，不启用非 WPS 生成器。
7. 即使只请求 DOCX，也必须内部导出临时 PDF 完成分页质量检查。
8. 只交付用户请求的 DOCX 或 PDF，内部 PDF 和暂存文件不得成为伴随产物。

## 非目标

- 不重构 PPTX 或 XLSX 生成。
- 不扩展现有 PDF 编辑器。
- 不自动生成统计图、知识图谱或业务分析数据。
- 不实现完整 CSL、EndNote 或 Zotero 文献管理。
- 不提供现有文档的语义级重新编辑。
- 不实现多人批注、修订模式或文档签名。
- 不新增 python-docx、LibreOffice 或手写 OOXML 备用生成链。
- 不承诺内部 Python 语义模型的第三方兼容性。

## 已确认的产品决策

1. 产品目标是通用高质量长文档引擎，不是样例模板复刻。
2. Windows COM 与 macOS JSAPI 必须同版本达到语义对齐。
3. 对外提供 Markdown 扩展语法；Python 结构化 API 仅供内部流水线使用。
4. 新长文档行为直接成为 `generate()` 默认行为。
5. 局部错误采用原位置降级，整体继续交付。
6. 引擎级致命错误立即终止。
7. 本轮只升级 DOCX 与由 WPS 原生导出的 PDF。
8. DOCX 必须经过内部临时 PDF 质量门。
9. 采用语义模型驱动方案，模板只提供样式资产。

## 总体架构

新引擎由六层组成。

### 1. Markdown 表达层

标准 Markdown 继续表达标题、段落、列表、普通表格、代码、图片和链接。
YAML frontmatter 与显式块指令表达摘要、分节、题注、公式、交叉引用和
参考文献。Markdown 不暴露 COM 常量、JSAPI 对象或绝对页面坐标。

### 2. 语义文档模型

`StructuredDocument` 扩展为长文档语义模型。模型描述内容的身份、关系和
版式意图，但不包含平台调用。新增概念包括：

- 文档节与前置页；
- 题注图像与语义表格；
- 题注、稳定 ID 和交叉引用；
- 编号公式；
- 参考文献与引用；
- 页眉、页脚、页码和目录配置；
- 局部降级标记。

### 3. 排版策略层

长文档策略统一决定页面、字体、目录密度、标题、表格、图像、公式、
参考文献、分页和降级标记。现有五个 preset 继续控制颜色、字体气质和
表格视觉变体，但不得破坏编号、字段、分页和质量规则。

### 4. 平台无关生成计划

Writer renderer 将语义模型转换成闭合、可序列化和可验证的操作计划。
生成计划只能包含允许的操作、纯 JSON 参数和逻辑资源 ID，不得包含任意
脚本、平台对象或未经资源策略验证的文件路径。

### 5. 双平台原生执行器

Windows 在 COM WriterComposer 中执行计划，macOS 在 WPS JSAPI add-in 中
执行相同语义操作。平台实现可以不同，但必须生成等价的标题、字段、题注、
页码、交叉引用、公式和降级标记。

### 6. 内部 PDF 质量门

WPS 保存暂存 DOCX 后，必须临时导出 PDF。共享质量检查器分析页面边界、
文本和对象位置。可恢复问题最多触发一次确定性重排；之后仍存在的局部
问题在相应位置形成降级标记。引擎级问题立即终止。

完整数据流：

```text
Markdown
  -> 语义模型
  -> 语义验证与规范化
  -> 排版策略
  -> 闭合生成计划
  -> WPS 原生执行
  -> 暂存 DOCX
  -> WPS 临时 PDF
  -> 质量检查与至多一次重排
  -> 原子发布请求格式
```

## 模块责任边界

### `document_model.py`

保存格式无关的语义数据。不得包含 COM、JSAPI、PDF 坐标或文件发布逻辑。

### `md_parser.py`

解析标准 Markdown、frontmatter 和长文档块指令。不得推断平台能力或直接
选择降级策略。

### 长文档策略模块

新增专用策略模块，保存默认页面、字体、目录、标题、图表、表格、公式、
参考文献和质量规则。避免继续扩大 `reference_styles.py` 的职责。

### `writer_renderer.py`

只负责语义节点到 Writer 操作的编排和对象顺序，不直接调用平台 API。

### `recording_composers.py` 与 `generation_plan.py`

共同构成闭合跨平台协议。新增操作必须先在共享模式中定义和验证，再由
两个平台实现。

### `writer.py`

实现 Windows COM 原生 Writer 原语。不得解析 Markdown 或复制共享策略。

### `macos/wps-jsapi-probe/addin/writer.js`

实现 macOS JSAPI 原生 Writer 原语。操作参数和失败语义必须与共享计划
一致。

### Writer 质量检查模块

新增 Writer 专用质量模块，负责 DOCX 语义快照、PDF 页面指标、问题定位和
重排建议。现有 `quality_checks.py` 的幻灯片职责保持不变。

## Markdown 公开契约

### 文档配置

```yaml
---
title: 决策即服务
author: 张三
date: 2026-08-20
header: 决策即服务：招投标数据分析
toc: true
figure_index: true
table_index: true
title_page: false
---
```

未提供的可选内容不构成错误。例如未声明 `figure_index`、文档中没有图像，
或未提供摘要，都按普通文档正常生成。

### 题注图像

```markdown
:::figure {#fig:supplier-network caption="供应商网络知识图谱" width="full"}
![[供应商网络.png]]
:::
```

`id` 在整个文档内唯一。`caption` 是可见题注文本。`width` 使用语义值，
首版支持 `auto`、`column`、`full` 和明确的点值。页面方向只能通过显式
`orientation="landscape"` 请求，不能根据图片比例自动改变。

### 语义表格

```markdown
:::table {#tab:node-properties caption="节点属性表" style="three-line"}
| 节点名称 | 属性名称 | 具体名称 |
|---|---|---|
| project | itemNumber | 项目编号 |
:::
```

首版表格样式支持 `three-line` 和 `grid`。未指定样式时由 preset 选择：
academic 默认三线表，business、consultant、tech 和 proposal 默认克制网格。

### 编号公式

```markdown
:::equation {#eq:common-neighbors}
CN(x,y)=|N(x)\cap N(y)|
:::
```

公式 ID 可被交叉引用。公式应使用 WPS 原生数学对象或跨平台语义等价的
WPS 原生结构；运行时失败才允许降级。

### 交叉引用

```markdown
供应商关系如 {{ref:fig:supplier-network}} 所示，
计算方式见 {{ref:eq:common-neighbors}}。
```

引用显示文本由目标类型和当前编号生成。未解析引用在原位置显示可读的
降级标记，不静默删除。

### 参考文献

```markdown
研究已经证明该方法有效 {{cite:chen2025}}。

:::bibliography
- id: chen2025
  text: 陈延超. 数字技术在工程建设招投标中创新应用研究[J]. 中国招标, 2025.
:::
```

首版只提供稳定 ID、引用序号、可读文献文本和统一样式，不实现 CSL 格式
引擎或外部文献管理器同步。

### 解析失败规则

- 不存在可选块时正常生成。
- 块已声明但资源不可用时生成语义节点，并在渲染阶段降级。
- 未解析交叉引用显示“引用目标未解析”。
- 重复 ID 以第一次定义为目标；后续对象取消引用能力并显示冲突标记。
- 未识别块保留原始文本并显示“未支持的排版指令”。
- 解析器不得静默丢失用户内容。

## 内部语义模型

内部模型至少需要表达以下字段。

### 文档和分节

- 文档标题、作者、日期、摘要、关键词；
- 是否生成标题页；
- 前置页、正文和参考文献节；
- 每节的页码格式、起始值、页眉、页脚和链接到前节策略；
- 是否包含正文目录、图目录和表目录。

### 题注对象

- 稳定 ID；
- 对象种类 `figure` 或 `table`；
- 题注正文；
- 章节式编号策略；
- 与对象的同页约束；
- 目录收录策略。

### 公式对象

- 稳定 ID；
- 原始数学表达式；
- 编号策略；
- 对齐方式；
- 原生渲染失败时的简化表示。

### 引用和参考文献

- 目标 ID；
- 引用种类；
- 显示格式；
- 文献 ID 和可见文本；
- 文献顺序和悬挂缩进规则。

### 降级问题

内部 issue 使用稳定结构：

```text
code
severity
node_id
message
fallback
recoverable
```

`message` 不得包含绝对路径、环境变量、token、密钥或调用栈。

## 默认排版规范

### 页面

- A4 纵向；
- 左边距 30mm；
- 右边距 25mm；
- 上边距 25.4mm；
- 下边距 25.4mm；
- 普通图片不得触发自动横向分节；
- 横向页面必须由语义节点显式请求。

### 正文

- 默认中文宋体 12pt；
- 默认英文和数字 Times New Roman 12pt；
- 两端对齐；
- 首行缩进 2 字符；
- 1.5 倍行距；
- 段前段后 0；
- preset 可以改变字体气质，但必须维持正文可读性和页面密度。

### 标题

- 一级标题黑体 16pt、左对齐；
- 二级标题黑体 15pt、左对齐；
- 三级标题黑体 14pt、左对齐；
- 四级标题黑体 12pt、左对齐；
- 标题与后续至少两行正文保持同页；
- 标题编号必须使用 WPS 原生列表或标题语义；
- 目录只收录配置允许的标题级别。

### 前置页与页码

- 标题页由 `title_page` 控制；
- 摘要、目录和图表清单使用罗马数字页码；
- 正文在新节中从阿拉伯数字 1 重新开始；
- 前置页默认不显示正文页眉；
- 正文页眉居中，并使用段落下边框形成页眉线；
- 页码在页脚居中显示，不强制添加 “Page” 前缀。

### 目录

- TOC 1：11pt、单倍行距、段前 3pt、段后 0；
- TOC 2/3：10.5pt、单倍行距、段前段后 0；
- 使用缩进表达层级，不插入空段落；
- 使用点引导线和右对齐页码；
- 图表清单使用相同紧凑规则；
- 目录末页利用率低于 35% 时先触发一次紧凑样式重排；
- 重排后仍低于 35% 记录 warning，不插入空白页，也不删除真实目录项。

### 图片和图表

- 图片居中并保持比例；
- 默认不超过正文宽度；
- 图题在图下方并与图片保持同页；
- 支持上下排列和明确的并排组合；
- 检查最终有效 DPI 和可读文字尺寸；有效 DPI 低于 150 记录可恢复问题；
- 低清图片仍可交付，但必须在原位置加入降级标记；
- 不负责生成图表内容，只负责原生编排现有资源。

### 表格

- 表题在表格上方；
- academic 默认三线表；
- 其他 preset 可以使用克制网格；
- 支持合并单元格、重复表头、列宽约束和单元格零缩进；
- 默认禁止表格行跨页拆分；
- 表题与至少第一行表格保持同页；
- 表内文字使用直接左、中、右对齐，不继承正文首行缩进。

### 公式

- 优先使用 WPS 原生数学对象；
- 公式居中，编号右对齐；
- 公式和编号保持同页；
- 编号和交叉引用可在字段更新后自动刷新；
- 原生公式运行时失败时降级为可读数学文本或图片并显示提示。

### 参考文献

- 使用统一悬挂缩进；
- 默认左对齐，避免中英文间距被两端拉伸；
- 引用序号风格由文档配置统一决定；
- 文献条目不得被空段落人为拉开；
- 中英文文献使用一致的段落间距和换行规则。

## 跨平台生成计划

共享计划新增以下语义操作：

- `writer.configure_front_matter`
- `writer.configure_section`
- `writer.configure_toc_styles`
- `writer.add_captioned_figure`
- `writer.add_semantic_table`
- `writer.add_equation`
- `writer.add_cross_reference`
- `writer.insert_figure_index`
- `writer.insert_table_index`
- `writer.add_bibliography`
- `writer.add_degradation_notice`
- `writer.finalize_fields`

每个操作必须具备：

- 明确的必需字段和可选字段；
- 纯 JSON 参数；
- 严格未知字段拒绝；
- 大小、数量和嵌套深度边界；
- 稳定错误码；
- Windows 和 macOS 等价测试。

## WPS 原生语义原则

- 标题、目录、页码、题注、交叉引用和公式优先使用 WPS 原生对象或字段。
- 平台 API 可以不同，最终语义和可编辑行为必须一致。
- 不要求 DOCX 字节一致，要求语义快照和 PDF 视觉结果一致。
- 新默认引擎不得依赖新增的 OOXML 后处理。
- 现有 `numbering_native.py` 在迁移期只服务旧链路。
- 新默认链路通过 WPS 原生列表和标题样式实现编号。
- 旧编号后处理只有在新链路跨平台验收通过后才从默认路径移除。

“WPS 原生等价结构”是指由 WPS API 创建、可在 WPS 中继续编辑，并且在
保存、重新打开和字段刷新后仍保持显示内容、更新行为和引用目标的对象或
字段组合。仅视觉相似的静态文本、图片或手写 OOXML 不属于等价结构。

## macOS 原生能力可行性门

正式实现前必须在真实 macOS WPS 中验证：

1. 分节页码格式和重新起始编号；
2. TOC 1/2/3 样式修改；
3. `SEQ` 题注字段；
4. 图目录和表目录；
5. 交叉引用字段；
6. Office Math 或等价 WPS 原生公式对象。

若直接 API 不存在，可以使用其他 WPS 原生结构，例如无边框表格承载公式
与右侧编号。不得转为静态 OOXML 拼补。无法形成跨平台等价语义的能力不得
进入 0.8.0。

## 错误与降级模型

### 正常缺省

文档没有图、表、公式、目录或参考文献时，直接按实际内容排版，不产生
提示或 warning。

### 可恢复局部问题

以下问题必须继续生成：

- 已声明图片不存在、损坏或插入失败；
- 公式对象创建失败；
- 表格无法按请求样式排版；
- 引用目标不存在或 ID 冲突；
- 某项高级格式在运行时不可用；
- 图片分辨率或标签尺寸低于质量要求。

处理顺序固定为：

1. 原生排版；
2. 一次确定性的简化排版；
3. 在原位置插入 `DegradationNotice`；
4. 继续后续内容；
5. 将 issue 加入内部 `GenerationOutcome`。

降级标记采用专业的浅黄色或浅灰色提示框，包含稳定错误码、对象名称、
可读原因和实际降级方式。

### 引擎级致命问题

以下情况立即终止：

- WPS 未安装、无法启动或 COM/JSAPI 不可用；
- WPS 保存失败；
- 注册恢复失败；
- DOCX 或 PDF 结构无效；
- 内部 PDF 无法导出；
- 原子发布或回滚失败。

致命错误不得启动非 WPS 备用生成器，也不得把不完整文件伪装为成功产物。

## 返回与交付契约

- 公开 `generate()` 继续返回绝对产物路径。
- 内部接口返回 `GenerationOutcome(path, degraded, issues)`。
- 局部问题既进入结构化 issue 列表，也在文档相应位置可见。
- 普通用户不额外收到诊断 JSON。
- 只发布请求的 DOCX 或 PDF。
- 内部 PDF、暂存 DOCX 和资源副本在成功后删除。
- 失败恢复所需的唯一副本按现有原子发布约定保留并报告。

## 质量门

### 生成顺序

1. Markdown 语义验证；
2. 生成计划闭合验证；
3. WPS 生成暂存 DOCX；
4. 验证标题、字段、题注、引用和媒体关系；
5. WPS 临时导出 PDF；
6. 执行 PDF 页面质量检查；
7. 可恢复问题最多触发一次重排；
8. 重新验证 DOCX 与 PDF；
9. 原子发布请求格式；
10. 删除内部证据和暂存文件。

### 确定性检查

- 非预期空白页；
- 页面内容超出正文区域；
- 页眉、页脚、页码格式和序列；
- 标题位于页尾且后续不足两行；
- 图题、表题与对象分离；
- 图片超宽或有效 DPI 过低；
- 表格超宽、表头未重复或行被拆分；
- 目录字号、行距、段间距和末页利用率；
- 题注断号、重复号或交叉引用未解析；
- 参考文献悬挂缩进和异常字符间距；
- 最后一页利用率过低。

最后一页利用率过低默认是 warning，不得删除真实内容。非预期空白页、
对象溢出和结构错误是必须修复的问题。

### 人工视觉检查

自动测试不能替代真实 WPS 和 PDF 视觉检查。每个里程碑至少检查代表性的
摘要、目录、正文、图、表、公式、代码、降级标记和参考文献页面。

## 里程碑

### M0：macOS 原生能力探针

验证分节页码、TOC 样式、题注、图表目录、交叉引用和公式能力。产出能力
矩阵、真实 DOCX/PDF 和截图证据，不进入正式 API。

通过标准：每项 0.8.0 能力在 Windows 与 macOS 都有 WPS 原生实现路径。

### M1：长文档语义核心

实现 Markdown 扩展、语义模型、ID/引用解析、排版策略和闭合计划。使用
recording composer 验证，不启动真实 WPS。

通过标准：同一输入稳定生成相同语义计划；缺省内容不报错；声明资源失败
产生降级节点。

### M2：页面骨架与目录

实现前置页、分节页码、页眉页脚、紧凑目录、标题层级和正文样式。

通过标准：两个平台真实生成的罗马页码、正文重启、页眉和目录密度正确，
没有意外空白页。

### M3：图、表与交叉引用

实现原生题注、章节式编号、图表清单、三线表、图片策略和交叉引用。

通过标准：移动、插入或删除图表后，WPS 更新字段即可重编号；图题和表题
不与对象分离。

### M4：公式、参考文献与降级系统

实现公式编号、公式引用、参考文献样式、引用序号、局部降级和文档内提示。

通过标准：所有局部故障都生成有效产物；所有引擎级故障立即终止。

### M5：PDF 质量门与默认迁移

实现内部 PDF、版式检查、一次重排、默认行为切换、文档和发布说明。

通过标准：所有真实验收夹具在两个平台通过，`generate()` 默认使用新引擎。

## 验收夹具

至少维护四类真实夹具：

1. 样例风格的密集学术报告；
2. 含宽图、长表和多章节的技术方案；
3. 含混合原生编号的技术标；
4. 故意缺图、引用错误和公式失败的降级文档。

每份夹具在 Windows 和 macOS 上验证：

- DOCX 原生字段和语义快照；
- WPS 打开并刷新字段后的结果；
- WPS 导出 PDF 的页面数量和页面边界；
- 页眉、页脚和页码序列；
- 目录密度、孤立标题和空白页；
- 图片 DPI、题注位置和表格跨页；
- 两个平台语义结果一致；
- 代表性页面人工截图检查。

## 兼容性和迁移

- 普通 Markdown 继续可用。
- `generate()` 签名和路径返回值保持兼容。
- 默认视觉和分页行为升级为新引擎。
- Markdown 扩展成为稳定公共契约。
- 内部 Python 模型不承诺第三方兼容。
- 提供一个过渡版本的 `layout_engine: legacy` frontmatter 开关。
- legacy 只用于历史文档应急，不接受新能力。
- 在 1.0 前根据真实使用情况决定是否移除 legacy。

## 版本与发布门

目标版本为 0.8.0。以下条件必须全部满足：

1. M0-M5 全部完成；
2. Windows 与 macOS 使用相同语义版本；
3. 全部平台无关测试通过；
4. Windows 和 macOS 真实 WPS 验收通过；
5. 四类验收夹具全部通过结构与 PDF 质量门；
6. README、SKILL、API 参考和长文档语法文档同步；
7. 插件清单和 Python 包版本一致；
8. 默认新引擎和 legacy 逃生路径分别通过验收；
9. 未跟踪的 `uv.lock` 和客户文档不进入提交或发布包。

任一平台未通过，不得宣称 0.8.0 长文档能力完成，也不得只发布另一平台。

## 文档交付

0.8.0 发布前必须更新：

- `README.md`：默认长文档行为、降级规则和示例；
- `skills/WPSComposer/SKILL.md`：真实能力、平台边界和生成流程；
- `skills/WPSComposer/references/api.md`：正确公共导入和 Markdown 契约；
- 新增 `docs/longform-markdown.md`；
- Windows 与 macOS 真实验收记录；
- 版本发布说明和迁移说明。

文档不得宣称未经真实 WPS 验收的能力已经可用。

## 安全和隐私

- 图片和附件只能通过受控资源清单进入计划；
- macOS 资源继续复制到私有 staging；
- 诊断信息不得泄露路径、token、环境变量或调用栈；
- 产物继续使用暂存、验证、原子发布和回滚；
- 局部降级不得绕过最终结构验证；
- 不联网获取缺失图片、公式或参考文献；
- 不把客户内容写入仓库验收夹具。

## 风险与缓解

### macOS WPS API 缺失

缓解：M0 先行；允许 WPS 原生等价结构，不允许 OOXML 拼补。无等价能力则
不进入 0.8.0。

### 跨平台字段刷新差异

缓解：比较语义快照和 WPS 导出 PDF，不比较 DOCX 字节；在两个平台分别
刷新字段并记录结果。

### 质量门误报

缓解：区分结构错误、可恢复问题和提示性 warning；重排最多一次；最后一页
低利用率不自动删减内容。

### 局部降级污染正式交付

缓解：标记使用专业样式、稳定错误码和最少必要信息；用户可定位并替换问题
资源；不以空白或静默丢失掩盖失败。

### 默认行为升级影响历史文档

缓解：0.8.0 发布说明明确行为变化；提供一个过渡版本的 legacy 开关；维护
旧输入与新引擎的回归夹具。

### 里程碑范围过大

缓解：M0-M5 各自产生独立、可测试交付物；实施阶段为每个里程碑编写独立
计划和审查门，不使用单一大提交完成全部工作。
