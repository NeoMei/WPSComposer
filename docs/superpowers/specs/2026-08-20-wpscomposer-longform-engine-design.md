# WPSComposer 原生长文档引擎升级设计

## 状态

- 设计日期：2026-08-20
- 目标版本：0.8.0
- 适用范围：Writer DOCX 生成与 WPS 原生 PDF 导出
- 设计状态：用户确认后经四轮实现可行性与反例复审修订
- 参考基准：`1011决策即服务：基于图谱的招投标数据挖掘与AI决策系统构建(2).pdf`

## 背景

WPSComposer 0.7.2 已具备样式驱动的 Writer 生成、原生目录、标题编号、
表格、图片、分节、页码字段、Windows COM 和 macOS JSAPI 生成链，以及
暂存、验证、原子发布和回滚。现有能力足以生成形式正规的报告，但还不能
稳定表达高质量长文档需要的完整语义，包括前置页、分节页码、紧凑目录、
原生题注、图表清单、交叉引用、公式编号、参考文献和布局质量门。

参考 PDF 是一份 43 页 A4 技术研究报告。值得吸收的部分包括：

- 摘要、目录、图表清单、正文和参考文献的完整长文档结构；
- 前置页罗马页码与正文阿拉伯页码重启；
- 正文页统一页眉、页眉线和页脚页码；
- 清晰的章节层级、章节式图表编号和交叉引用；
- 三线表、数学公式、统计图、图谱、代码和系统截图的混合编排；
- 宋体与 Times New Roman 的中英文混排。

不应复制的缺点包括：

- 目录和图表清单条目间距过大；
- 目录末页利用率过低；
- 部分图表标签缩小到难以阅读；
- 个别页面和最终参考文献页留白过多；
- 参考文献中英文间距、换行和对齐不统一；
- 通过静态图片或普通文本模拟本应可编辑的文档语义。

升级目标不是复刻一个固定模板，而是建立可复用于学术报告、技术方案和
技术标的通用高质量长文档引擎。

## 目标

1. 让 `generate()` 的 DOCX/PDF 分支默认使用新的长文档排版行为，PPTX/XLSX
   分支保持现有行为。
2. 以 Markdown 作为稳定公开输入，以内部语义模型承载长文档结构。
3. 在 Windows COM 与 macOS JSAPI 上提供相同的 WPS 原生语义。
4. 使用 WPS 原生字段和对象实现标题、目录、页码、题注、交叉引用和公式。
5. 局部内容或排版错误必须在原位置降级并继续交付有效产物。
6. WPS 引擎不可用、保存失败或产物无效时立即失败，不启用非 WPS 生成器。
7. 即使只请求 DOCX，也必须内部导出临时 PDF 完成分页质量检查。
8. 只交付用户请求的 DOCX 或 PDF，内部 PDF 和暂存文件不得成为伴随产物。

## 非目标

- 不重构 PPTX 或 XLSX 生成。
- 不扩展现有 PDF 编辑器。
- 不自动生成统计图、知识图谱或业务分析数据。
- 不实现完整 CSL、EndNote 或 Zotero 文献管理。
- 不提供现有文档的语义级重新编辑。
- 不实现多人批注、修订模式或文档签名。
- 不新增 python-docx、LibreOffice 或手写 OOXML 备用生成链。
- 不承诺内部 Python 语义模型的第三方兼容性。

## 已确认的产品决策

1. 产品目标是通用高质量长文档引擎，不是样例模板复刻。
2. Windows COM 与 macOS JSAPI 必须同版本达到语义对齐。
3. 对外提供 Markdown 扩展语法；Python 结构化 API 仅供内部流水线使用。
4. 新长文档行为直接成为 `generate()` 的 DOCX/PDF 默认行为。
5. 局部错误采用原位置降级，整体继续交付。
6. 引擎级致命错误立即终止。
7. 本轮只升级 DOCX 与由 WPS 原生导出的 PDF。
8. DOCX 必须经过内部临时 PDF 质量门。
9. 采用语义模型驱动方案，模板只提供样式资产。

## 总体架构

新引擎由六层组成。

### 1. Markdown 表达层

标准 Markdown 继续表达标题、段落、列表、普通表格、代码、图片和链接。
YAML frontmatter 与显式块指令表达摘要、分节、题注、公式、交叉引用和
参考文献。Markdown 不暴露 COM 常量、JSAPI 对象或绝对页面坐标。

### 2. 语义文档模型

`StructuredDocument` 扩展为长文档语义模型。模型描述内容的身份、关系和
版式意图，但不包含平台调用。新增概念包括：

- 文档节与前置页；
- 题注图像与语义表格；
- 题注、稳定 ID 和交叉引用；
- 编号公式；
- 参考文献与引用；
- 页眉、页脚、页码和目录配置；
- 局部降级标记。

### 3. 排版策略层

长文档策略统一决定页面、字体、目录密度、标题、表格、图像、公式、
参考文献、分页和降级标记。现有五个 preset 继续控制颜色、字体气质和
表格视觉变体，但不得破坏编号、字段、分页和质量规则。

### 4. 平台无关生成计划

Writer renderer 将语义模型转换成闭合、可序列化和可验证的操作计划。
生成计划只能包含允许的操作、纯 JSON 参数和逻辑资源 ID，不得包含任意
脚本、平台对象或未经资源策略验证的文件路径。计划协议必须带版本，并在
执行前与平台执行器完成能力握手；版本或能力不匹配时不得开始修改文档。

### 5. 双平台原生执行器

Windows 在 COM WriterComposer 中执行计划，macOS 在 WPS JSAPI add-in 中
执行相同语义操作。平台实现可以不同，但必须生成等价的标题、字段、题注、
页码、交叉引用、公式和降级标记。执行器按白名单区分可恢复的对象级错误
和不可恢复的引擎级错误，并返回结构化 issue 与分页定位快照。

### 6. 内部 PDF 质量门

WPS 保存暂存 DOCX 后，必须临时导出 PDF。共享质量检查器结合 WPS 分页
定位快照分析页面边界、文本和对象位置，并把 PDF 页面问题映射回稳定
`node_id`。可恢复问题最多触发一次确定性重排；之后仍存在的局部问题在
相应位置形成降级标记。引擎级问题立即终止。

完整数据流：

```text
Markdown
  -> 语义模型
  -> 语义验证与规范化
  -> 资源预检；缺失资源转为降级节点
  -> 排版策略
  -> 带版本的闭合生成计划
  -> 执行器能力握手
  -> WPS 原生执行与分页定位快照
  -> 暂存 DOCX
  -> WPS 临时 PDF
  -> PDF 问题映射、质量检查与至多一次重排
  -> 原子发布请求格式
```

## 模块责任边界

### `document_model.py`

保存格式无关的语义数据和预计降级。不得包含 COM、JSAPI、PDF
坐标、运行期 `GenerationIssue` 或文件发布逻辑。

### `md_parser.py`

解析标准 Markdown、frontmatter 和长文档块指令。不得推断平台能力或直接
选择降级策略。普通可见文本在进入语义模型前统一规范化为 Unicode NFC；
代码块原文保持不变，并在语义节点中标记 `normalization: none`。

### 长文档策略模块

新增专用策略模块，保存默认页面、字体、目录、标题、图表、表格、公式、
参考文献和质量规则。避免继续扩大 `reference_styles.py` 的职责。

### `writer_renderer.py`

只负责语义节点到 Writer 操作的编排和对象顺序，不直接调用平台 API。

### `recording_composers.py` 与 `generation_plan.py`

共同构成闭合跨平台协议。新增操作必须先在共享模式中定义和验证，再由
两个平台实现。协议负责版本、阶段顺序、稳定节点 ID、失败策略和返回结果
结构，不把这些规则分散到平台实现中。

### `writer.py`

实现 Windows COM 原生 Writer 原语。不得解析 Markdown 或复制共享策略。

### `windows_writer_worker.py`

新增独立 worker 进程执行 DOCX/PDF 长文档计划。worker 只能使用
`DispatchEx` 或经 M0 证明具有独立进程所有权的等价创建方式，必须记录自己
拥有的 WPS 进程标识。长文档路径不得退回可能连接用户交互实例的普通
`Dispatch`。无法证明专属实例所有权时，在修改文档前抛出
`WINDOWS_DEDICATED_HOST_UNAVAILABLE`。

现有低层 Composer API 可以维持兼容 fallback，但不得被新默认长文档路径
调用。主进程只负责计划验证、监督、超时、结果接收和原子发布。

### `macos/wps-jsapi-probe/addin/writer.js`

实现 macOS JSAPI 原生 Writer 原语。操作参数和失败语义必须与共享计划
一致。

### Writer 质量检查模块

新增 Writer 专用质量模块，负责 DOCX 语义快照、PDF 页面指标、问题定位和
重排建议。WPS 执行器生成的
`node_id -> sections/page_span/range/fragments` 分页快照
是运行期 `GenerationIssue` 定位和可见提示回写的唯一依据，不在正文
插入隐藏哨兵文本。现有
`quality_checks.py` 的幻灯片职责保持不变。

## Markdown 公开契约

### 文档配置

```yaml
---
title: 决策即服务
short_title: 决策即服务
author: 张三
date: 2026-08-20
header: 决策即服务：招投标数据分析
heading_numbering: auto
toc: true
figure_index: true
table_index: true
title_page: false
---
```

未提供的可选内容不构成错误。例如未声明 `figure_index`、文档中没有图像，
或未提供摘要，都按普通文档正常生成。

缺省值必须确定且跨平台一致：

- `title`：优先使用 frontmatter；否则使用第一个 H1；仍不存在则为空；
- `title_page: auto`：标题非空且存在作者或日期时生成，否则不生成；显式
  布尔值优先；
- `toc: auto`：正文中可收录的 H1-H3 标题达到 3 个，并且去除 Markdown
  控制符、frontmatter 与空白后的正文达到 3000 个 Unicode code point 时
  生成，否则不生成；
- `figure_index: false`；
- `table_index: false`；
- `bibliography_include_uncited: true`；
- `caption_numbering: auto`：对象之前存在已编号 H1 时使用章节式编号，否则
  使用全局连续编号；未编号 H1 不重置图、表或公式序列；
- `heading_numbering: auto`：识别并规范化受支持的中文正式、纯十进制和技术标
  混合层级；也可显式使用 `none`、`chinese-formal`、`decimal` 或
  `hybrid-bid`；
- `header`：优先使用显式值，其次使用 `short_title`，最后使用文档标题；
  标题为空时不生成正文页眉文字；
- `layout_engine: longform`：仅 DOCX/PDF 生效。

已识别的上述布局键若值类型或枚举无效，使用该键的明确缺省值继续，并生成
文档级 `CONFIG_VALUE_INVALID` 降级提示，不把它当作引擎故障。其他业务 frontmatter
键可作为普通元数据保留，不因 WPSComposer 不识别而报错或写入正文。

显式或自动启用的 TOC、图目录或表目录只在至少有一个可收录对象时
插入；对象数为零时直接省略该前置页，不产生空页、提示或 warning。
这属于“内容本就不存在”的正常排版，不是降级。

`auto` 只依赖语义模型，不依赖平台、字体测量或首次分页结果，保证同一输入
在两个平台选择相同的文档结构。页眉显示文本也在语义层一次性确定：
使用插件内置且固定为 Unicode 15.1.0 的 UAX #29 扩展字素簇和东亚宽度表。
每个扩展字素簇中含宽字符、全角字符、东亚宽度为 ambiguous 的
字符或 emoji 时计 2 个显示单位，其他字素簇计 1；组合符和 ZWJ 序列不得
拆开。超过 64 个显示单位时，在不超过 62 个单位的最后字素边界后加
全角省略号，并生成文档级 `HEADER_SHORTENED` 降级提示。两个平台使用
同一已截短文本，不得各自按字体测量重新截取，也不修改文档正式标题。
已截短文本在已批准字体的 9pt 下仍溢出时属于 `HEADER_OVERFLOW` 高置信度
排版问题，进入唯一一次确定性重排；降级为不超过 32 个显示单位的同规则
文本并显示文档级提示，不允许换行或侵入正文区。

解析后的文档标题必须恰好可见一次：生成标题页时只出现在标题页；
不生成标题页时在正文开头以 Title 样式显示，不进入章节编号或 TOC。
标题来自第一个 H1 时，该 H1 被消耗为文档标题；显式 frontmatter 标题与
第一个 H1 在 NFC 规范化和去除首尾空白后相同时，也消耗该重复 H1。
两者不同时，frontmatter 标题仍按上述规则显示，第一个 H1 保留为正文章节。
显式 `title_page: true` 但解析后标题为空时，省略空封面，并在文档开头生成
文档级 `TITLE_MISSING` 提示。

### 前置内容与显式分页

摘要和关键词使用闭合块表达：

```markdown
:::abstract
本文构建基于图谱的招投标数据挖掘与 AI 决策方法。
:::

:::keywords
知识图谱；招投标；AI 决策
:::
```

`abstract` 和 `keywords` 各最多一个，无论在源文件中出现于何处，都被提取到
正文目录之前的前置节。`abstract` 允许普通段落、行内格式和列表，不允许
标题、图、表、公式或分页块；出现这些子节点时按可读纯文本保留，并在摘要
内原位插入 `ABSTRACT_CONTENT_DEGRADED` 行内或块级提示。`keywords` 使用中文
分号、英文分号或换行分隔，去除首尾空白和空项后以“关键词：”单段显示。
不存在摘要或关键词时正常省略，不生成空前置页。

同类块重复时，第一个作为前置内容；后续块不得丢弃，按原始顺序在正文位置
转为可读普通内容，并加入 `DUPLICATE_FRONT_MATTER_BLOCK` 块级提示。

用户显式分页只使用空块：

```markdown
:::page-break
:::
```

它生成 WPS 原生分页符，不生成新节，也不改变页面方向、页码或页眉页脚。
非空 `page-break` 块的内容在分页后按普通段落保留，并加入
`PAGE_BREAK_CONTENT_DEGRADED` 块级提示。由该块产生的稀疏页面标记为用户显式
分页，不参与普通正文利用率警告；连续两个分页块仍保留用户意图。

`heading_numbering: auto` 只识别闭合的已支持前缀并把它们转换为原生列表
意图，插入 WPS 前移除可见文本前缀。无法识别的手工前缀原样保留，并将该
标题标记为 `numbering: none`，防止双重编号。任何自动检测结果都必须进入
语义快照，两个平台不得各自重新检测。

三种编号方案的层级契约固定为：以下 H1-H4 均指文档标题消耗之后的
源 Markdown 标题级别：

- `chinese-formal`：H1 `第一章`、H2 `第一节`、H3 `一、`、H4 `（一）`；
- `decimal`：H1 `1`、H2 `1.1`、H3 `1.1.1`、H4 `1.1.1.1`；
- `hybrid-bid`：H1 `第一章`、H2 `1.1`、H3 `1.1.1`、H4 `关键工法01：`。

其中中文数字只接受零、〇、一至十、百、千和两的合法组合；除
`hybrid-bid` H4 的固定工法格式外，阿拉伯数字段必须是不带前导零的
正整数。前缀必须从标题首字符开始；中文终止标点后可无空格，
无终止标点的十进制前缀后必须至少有一个空白字符，避免把年份或普通数字当成编号。
`hybrid-bid` H4 接受 `关键工法` 后 1-3 位数字和中英文冒号，输出保持
两位起始格式且在全文连续，不随 H1-H3 重启。`chinese-formal` 和
`hybrid-bid` 与 0.7.2 已验证的原生多级编号视觉语义保持兼容，`decimal`
保留现有阿拉伯多级序列语义并在 0.8.0 中补齐原生链接验收。新引擎改用
WPS 原生 API 创建结构，不复用旧 OOXML 后处理。

`auto` 先对整份文档一次性评分。没有手工前缀时，若超过一半可编号 H1-H4
标题至少含一个 Unicode `Script=Han` 字符，选择 `chinese-formal`，否则选择
`decimal`；不得只检查基本中日韩统一表意文字区，扩展汉字也必须识别。空标题不进入
比例分母。`Script=Han` 判定也必须使用上述同一份 Unicode 15.1.0 内置表。
存在前缀时，只有唯一候选方案至少匹配两个标题，或匹配
一个不可能属于其他方案的前缀，且没有层级冲突时才选中该方案。其他
情况按上述汉字比例选择 `chinese-formal` 或 `decimal` 作为确定性并列规则。
选定方案后逐标题处理：与方案及层级相符的已有前缀正常移除并绑定原生
编号；只有不相符的前缀才原样保留、取消该标题的原生编号，并生成
文档级 `HEADING_PREFIX_AMBIGUOUS` 降级提示。仅因 `chinese-formal` 和
`hybrid-bid` 在 H1 都使用“第一章”而得分并列，不构成需要提示的冲突。显式方案
不执行文档级推断；只移除与该方案和标题层级完全相符的前缀。已移除
前缀中的数值只是方案识别线索，不是输出起始值；最终数值由 WPS 关联多级列表
按标题顺序重新计算，插入、移动或删除后必须自动重排。

解析后存在文档标题时，在第一个已编号 H1 之前出现的 H2-H6 按首章前的前言
标题处理：保留源 Heading 样式、大纲级别和 TOC 资格，但不绑定原生编号，
不整体上移级别，也不生成降级提示。这与 0.7.2 已验证的“文档标题与第一章
之间可存在未编号前言标题”行为保持兼容。
没有解析出文档标题且源文档直接从 H2-H6 开始时，不适用前言例外，按下述
层级缺失规则处理。

除上述首章前的前言例外，H2-H4 只有在当前结构栈中存在所有必需父级
时才绑定原生多级编号。层级跳跃造成父级缺失时，保留该标题的 Heading
样式、大纲级别和 TOC 资格，将它及其依赖缺失父级的后续子标题标记为
`numbering: none`，并生成文档级 `HEADING_LEVEL_GAP` 降级提示。不得合成隐藏
父标题，也不得输出 `0.1` 类伪编号。父级因语义规范化标记为
`numbering: none` 或已有
前缀冲突而不编号时，其子树跟随保持不编号，但不重复生成层级缺失提示。
新的合法同级或更高级已编号标题出现后恢复正常结构栈。H5-H6 保留原生
Heading 样式但在 0.8.0 中不参与自动编号；它们只在目录级别显式扩展时进入 TOC。
`heading_numbering: none` 是整份文档的明确关闭开关；此时所有标题都不编号，
不执行父级缺失检查，也不生成 `HEADING_LEVEL_GAP`。

### 题注图像

```markdown
:::figure {#fig:supplier-network caption="供应商网络知识图谱" width="full" orientation="portrait" kind="diagram"}
![[供应商网络.png]]
:::
```

图、表和公式块的显式公开 ID 可选；未提供时使用规范化遍历顺序生成内部
稳定 ID，对象仍然参与题注编号和目录，但不得作为用户可书写的交叉引用目标。
提供时，公开 ID 必须匹配 `^[A-Za-z][A-Za-z0-9._:-]{0,127}$`，不得使用保留前缀
`__wpsc_`，并在图、表、公式、交叉引用目标和参考文献之间全局唯一。`caption`
是可见题注文本。`width` 使用语义值，
首版支持 `auto`、`column`、`full` 和带 `pt` 后缀的明确点值，例如
`360pt`。页面方向只能通过显式 `orientation="landscape"` 请求，不能根据
图片比例自动改变。`kind` 支持 `auto`、`photo`、`scan`、`screenshot` 和
`diagram`，用于选择质量规则；`auto` 不确定时按通用 DPI warning 处理，
不得擅自判定标签不可读。

`:::figure` 和 `:::table` 的 `caption` 必须是去除首尾空白后的非空文本。
缺失或为空时仍保留并排版图像/表格数据，但不创建 `SEQ` 题注、图表目录项
或可交叉引用的目标，并在对象位置生成 `CAPTION_MISSING` 块级提示。
指向该显式 ID 的引用按未解析引用处理。不带语义块的普通 Markdown 图片不要求
题注，也不因没有题注而降级。

首版并排图使用同一个 figure 块表达，最多两张图片：

```markdown
:::figure {#fig:model-compare caption="模型结果对比" layout="columns" columns="2"}
![[模型A.png]]
![[模型B.png]]
:::
```

`layout` 首版只支持 `stack` 和 `columns`；`columns` 只允许两张图片。整个
组合共享一个原生题注和编号。更多图片、独立子题注和任意网格不进入 0.8.0。
组合内每张图片都有稳定子节点 ID 并独立预检。子 ID 固定为
`<figure-stable-id>/image:<1-based-ordinal>`；斜杠不属于公开 ID 字符集，因此该派生
命名空间不会与用户 ID 冲突。两张图中只有一张失败时，
保留成功图片，改为 `stack`，在题注之前的失败子节点位置插入块级提示；
全部失败时用包含题注名称的块级提示代替图像区。两种情况都保留共享原生
题注、编号、目录项和交叉引用目标，不因子资源故障删除整个 figure。

0.8.0 确定支持 PNG、JPEG、TIFF、BMP 和 GIF。格式以 Pillow 完整解码的
签名结果为准，不根据扩展名放行。单帧且无 EXIF 方向变换的已验证资源
原样交给 WPS；多帧 GIF 或多页 TIFF 只使用第一帧/页，并生成
`MULTIFRAME_FLATTENED` 降级提示。需要取帧或方向转换时，保留可用的 ICC
配置，将规范化像素以内部无损 PNG 资源副本交给 WPS；这是明确的栅格资源
规范化，不是布局备用引擎。单个资源受 50 MiB、8000 万像素和单边
不超过 32768 像素的预检边界；Pillow 解压炸弹警告按无效资源处理，
不允许关闭保护后继续。内部 PNG 只存在于暂存资源目录，成功或失败清理时
都按原子发布的资源清理规则删除。

SVG 必须在 M0 证明两个平台都能由 WPS 原生插入、保存和导出后才进入允许
清单；即使能力通过，也只允许静态 SVG，拒绝脚本、`foreignObject`、外部
URL、外部字体和非 data URI 的引用，并在任何 XML 解析前拒绝
`DOCTYPE` 和实体声明。SVG 最多 100000 个 XML 元素、最大嵌套深度 256；
超限时按不支持资源降级，不得递归强行解析。data URI 的解码后字节也计入
单资源大小上限；
其中嵌入的栅格图还必须通过相同的像素、边长和解压炸弹检查。否则按
不支持资源在原位置降级，不得静默调用非 WPS 栅格化备用链。

### 语义表格

```markdown
:::table {#tab:node-properties caption="节点属性表" style="three-line" orientation="portrait"}
| 节点名称 | 属性名称 | 具体名称 |
|---|---|---|
| project | itemNumber | 项目编号 |
:::
```

首版表格样式支持 `three-line` 和 `grid`。未指定样式时由 preset 选择：
academic 默认三线表，business、consultant、tech 和 proposal 默认克制网格。
`orientation` 支持 `portrait` 和 `landscape`。`merges` 使用以分号分隔的 A1
范围，例如 `A1:B1;A2:A3`；被覆盖单元格必须为空，冲突、越界或非矩形合并
时不得丢弃表格数据；忽略全部合并范围，用完整未合并网格排版，并在表题
后插入 `TABLE_MERGE_INVALID` 块级提示。合并范围不得重叠，也不得跨越
重复表头与正文边界。表头内部只允许横向合并。正文纵向合并必须作为
不可拆分行组；若该行组高于一页，降级为完整未合并网格并显示提示。
未声明 `merges` 时按普通矩形表生成。原生表格样式应用失败时先降级为完整
普通网格；连普通网格都无法插入时，保留表题和按行分隔的纯文本数据，
并插入 `TABLE_INSERT_FAILED` 块级提示。

### 编号公式

```markdown
:::equation {#eq:common-neighbors}
CN(x,y)=|N(x)\cap N(y)|
:::
```

公式 ID 可被交叉引用。公式内容必须使用 Office Math 或 WPS 原生公式对象；
无边框表格只允许作为“公式居中、编号右对齐”的布局容器，不能替代数学
对象。原始受限 LaTeX 文本只能作为运行期降级，不能计入原生能力通过；
只有用户通过公式块的可选 `fallback_image="relative/path.png"` 属性显式提供
已通过相同资源预检的图片时，才允许把它作为降级资源。系统不自动调用
非 WPS 公式转图引擎，`fallback_image` 也不参与原生能力验收。

首版公式输入是受限 LaTeX 数学子集，支持常用上下标、分式、根式、求和、
积分、矩阵、括号和希腊字母。单个公式最长 10000 个 Unicode code point，
花括号嵌套不超过 64 层。禁止自定义宏、包声明、文件读写、`\input`、
`\include`、`\write`、shell escape 和外部资源引用。未知命令在语义
预检阶段产生公式降级节点，不交给 WPS 猜测执行。

### 交叉引用

```markdown
供应商关系如 {{ref:fig:supplier-network}} 所示，
计算方式见 {{ref:eq:common-neighbors}}。
```

引用显示文本由目标类型和当前编号生成。未解析引用使用同一段落内的
`InlineDegradationSpan` 显示可读占位，不插入块级提示框，也不静默删除。

### 参考文献

```markdown
研究已经证明该方法有效 {{cite:chen2025}}。

:::bibliography
- id: chen2025
  text: 陈延超. 数字技术在工程建设招投标中创新应用研究[J]. 中国招标, 2025.
:::
```

首版只提供稳定 ID、引用序号、可读文献文本和统一样式，不实现 CSL 格式
引擎或外部文献管理器同步。数字序号按正文首次引用顺序分配，重复引用复用
同一序号；未被引用的已声明条目在已引用条目之后按声明顺序继续编号，除非
显式设置 `bibliography_include_uncited: false`。缺失文献 ID 使用
`InlineDegradationSpan`，重复文献 ID 遵循全局重复 ID 规则。

### 解析失败规则

- 不存在可选块时正常生成。
- 块已声明但资源不可用时保留语义节点，并在资源预检阶段规范化为降级节点。
- 未解析交叉引用显示“引用目标未解析”。
- 重复 ID 以第一次定义为目标；后续对象取消引用能力并显示冲突标记。
- 未识别块保留原始文本并显示“未支持的排版指令”。
- 解析器不得静默丢失用户内容。

## 内部语义模型

内部模型至少需要表达以下字段。

### 文档和分节

- 文档标题、作者、日期、摘要、关键词；
- 是否生成标题页；
- 前置页、正文和参考文献节；
- 页面角色，包括标题页、摘要、目录、图表清单、正文、章节首页和参考文献；
- 每节的页码格式、起始值、页眉、页脚和链接到前节策略；
- 是否包含正文目录、图目录和表目录。

### 题注对象

- 稳定 ID；
- 对象种类 `figure` 或 `table`；
- 图像资源列表、排列方式、表格合并范围和显式页面方向；
- 资源状态 `ready`、`missing`、`invalid` 或 `unsupported`；
- 题注正文；
- 章节式编号策略；
- 与对象的同页约束；
- 目录收录策略。

章节式图、表和公式编号绑定最近的已编号 H1 原生列表值。文档没有已编号
H1，或对象位于第一个已编号 H1 之前时，使用全局序号。0.8.0 不从
标题文字猜测“附录”，也不自动生成附录字母编号；附录专用语义留待后续版本。
章节式显示固定为“图 1-1”、“表 1-1”和“(1-1)”，全局显示为
“图 1”、“表 1”和“(1)”。章节分量使用 H1 原生列表的数值计数器并
以阿拉伯数字显示，不复制“第一章”的可见文本。图、表、公式分别使用
独立 `SEQ` 序列，并在每个已编号 H1 处重启；未编号 H1 不重启。两个平台
必须通过原生字段或可在 WPS 刷新的等价原生结构获取该计数器，不得写入
一次性静态章号。

### 公式对象

- 稳定 ID；
- 原始数学表达式；
- 编号策略；
- 对齐方式；
- 原生渲染失败时的简化表示。

### 引用和参考文献

- 目标 ID；
- 引用种类；
- 显示格式；
- 文献 ID 和可见文本；
- 文献顺序和悬挂缩进规则。

### 计划降级与运行期 issue

`StructuredDocument` 只能保存与平台和分页无关的 `PlannedDegradation`：

```text
code
node_id
message
fallback
placement
```

WPS 执行和 PDF 质量门产生独立的 `GenerationIssue`，不得把页码或 PDF 坐标
回写到语义模型：

```text
code
severity
node_id
stage
message
fallback
recoverable
page
page_label
placement
confidence
evidence
```

`page` 是从 1 开始的 PDF 物理页序，`page_label` 是文档中的可见页码标签，
例如 `iv` 或 `3`；两者在分页前都可以为空。问题覆盖多页时，`page` 使用
首个确认受影响的物理页，完整页集合写入 evidence。`evidence` 只保存
可序列化的页码、bbox、字号、DPI、字段状态和阈值，不保存客户正文。
`message` 和 `evidence` 不得包含绝对路径、环境变量、token、密钥或调用栈。
预检问题转换为 `GenerationIssue` 时默认 `confidence: high`，但原始
`PlannedDegradation` 仍保持无页面、无坐标。

`placement` 只能是：

- `inline`：引用、文献引用和行内公式，在原段落中显示；
- `block`：图片、表格、块公式和其他独立对象，在原块位置显示；
- `document`：字体替换等影响整份文档的问题，放在标题页之后、首个目录或
  正文之前的“生成质量提示”区域。

用户显式声明的图、表、公式和引用 ID 在语义模型中原样保留，但不得使用
保留前缀 `__wpsc_`。普通标题、段落、列表项和未带公开 ID 的语义块使用
规范化文档遍历顺序生成
内部 ID，例如 `__wpsc_para:2:17`；显式 ID 和内部 ID 使用不同命名空间。
同一份规范化输入必须得到相同 ID。第二次重排和 notice-only patch 必须
复用首次分配的 ID，不得根据新页码重新编号。

## 默认排版规范

### 页面

- A4 纵向；
- 左边距 30mm；
- 右边距 25mm；
- 上边距 25.4mm；
- 下边距 25.4mm；
- 普通图片不得触发自动横向分节；
- 横向页面必须由语义节点显式请求。

### 正文

- 默认中文宋体 12pt；
- 默认英文和数字 Times New Roman 12pt；
- 两端对齐；
- 首行缩进 2 字符；
- 1.5 倍行距；
- 段前段后 0；
- preset 可以改变字体气质，但必须维持正文可读性和页面密度。

### 字体能力与跨平台等价

排版策略使用逻辑字体角色，不把平台字体显示名称直接散落到 renderer：

- `body_cjk`：Windows 首选宋体，macOS 首选 Songti SC 或经 M0 验证的华文宋体；
- `heading_cjk`：Windows 首选黑体，macOS 首选 Heiti SC 或经 M0 验证的华文黑体；
- `latin`：首选 Times New Roman，缺失时使用经 M0 验证的 Times；
- `mono`：Windows 首选 Consolas，macOS 首选 Menlo。

能力握手必须通过 WPS 实际字体集合，而不是只检查操作系统字体目录。最终
保存后重新读取正文、标题、表格、题注和代码样式的实际字体，并检查 PDF
使用的字体名称。使用上述已批准的平台等价字体不构成降级；落入 WPS 未知
替代字体时产生 `FONT_SUBSTITUTED` 文档级降级提示，但仍继续输出。PDF
字体比对先去掉嵌入子集的六位大写前缀和 `+`，再按已批准的 PostScript
别名表归一化；不得因 PDF 子集名称不同误报字体替换。

双平台 PDF 验收要求页面尺寸、边距、分节数和方向完全一致；当两个平台使用
不同的已批准等价字体时，总页数差不得超过 `max(1, ceil(较大页数 * 2%))`，
对应章节首页页码差不得超过 1，且任一平台都不得出现溢出、孤立标题、题注
分离或额外空白页。两个平台实际使用同一字体文件时以页数完全一致为目标；
若 WPS 布局引擎差异仍落在上述容差内，可在验收记录说明后通过，不把字节
或绝对分页相同当作跨平台语义等价的前提。

### 标题

- 一级标题黑体 16pt、左对齐；
- 二级标题黑体 15pt、左对齐；
- 三级标题黑体 14pt、左对齐；
- 四级标题黑体 12pt、左对齐；
- 标题与后续至少两行正文保持同页；
- 标题编号必须使用 WPS 原生列表或标题语义；
- 目录只收录配置允许的标题级别。

### 前置页与页码

- 标题页由 `title_page` 控制；
- 标题页不显示页码，也不计入前置页罗马数字序列；
- 摘要、目录和图表清单使用小写罗马数字页码 `i, ii, iii, ...`；
- 正文在新节中从阿拉伯数字 1 重新开始；
- 不存在摘要、目录或图表清单时，正文直接从阿拉伯数字 1 开始；
- 前置页默认不显示正文页眉；
- 正文页眉居中，并使用段落下边框形成页眉线；
- 页码在页脚居中显示，不强制添加 “Page” 前缀。

显式横向图或表使用 WPS 原生“下一页”分节符进入横向节，不得使用
奇数页或偶数页分节符。后续再有纵向内容时，使用另一个“下一页”分节符
恢复纵向；横向对象已是文档最后内容时不创建空的尾部纵向节。相邻横向
对象在没有用户显式分页时共用同一横向节。

这些临时方向节的页码必须继续前一正文节，不重启编号；页眉页脚在正文节
之间使用原生“链接到前一节”或等价引用，但不得回链封面和前置页的页眉
页脚。执行后必须检查没有空 section body、没有意外空白页，并对位于正文
首个、中部和末尾的横向对象分别验收。

### 目录

- TOC 1：11pt、单倍行距、段前 3pt、段后 0；
- TOC 2/3：10.5pt、单倍行距、段前段后 0；
- 唯一一次紧凑重排的下限为 TOC 1 10.5pt、TOC 2/3 10pt、全部段前段后 0；
- 使用缩进表达层级，不插入空段落；
- 使用点引导线和右对齐页码；
- 图表清单使用相同紧凑规则；
- 末页利用率规则只适用于占两页以上的目录或图表清单；
- 末页利用率低于 35%，且在不低于上述最小字号和间距的前提下可以回流到
  前页时，触发一次紧凑样式重排；
- 重排后自然留下的稀疏末页仅记录信息性 warning，不插入文档内降级框、
  不插入空白页，也不删除真实目录项；
- 单页短目录不执行 35% 利用率检查。

### 图片和图表

- 图片居中并保持比例；
- 默认不超过正文宽度；
- 图题在图下方并与图片保持同页；
- 支持上下排列和明确的并排组合；
- 检查最终有效 DPI 和可读文字尺寸；照片或扫描件的有效 DPI 低于 150
  记录 warning；
- 图片无法解码或有效 DPI 低于 96 时，记录可恢复问题并在原位置加入降级
  标记；
- UI 截图和线条图不得只因低于 150 DPI 自动加入可见标记，仍须根据最终
  尺寸和文字可读性判断；
- 标签字号只有在矢量源、已声明资源元数据或可靠文字边界可用时才能自动
  检查；最终估算低于 8pt 时记录可恢复问题，否则留给人工视觉验收；
- 不负责生成图表内容，只负责原生编排现有资源。

### 表格

- 表题在表格上方；
- academic 默认三线表；
- 其他 preset 可以使用克制网格；
- 支持合并单元格、重复表头、列宽约束和单元格零缩进；
- 默认禁止表格行跨页拆分；
- 单行内容高于可用页面高度时，禁止保持规则造成溢出；该行允许跨页拆分，
  并在表题后加入 `TABLE_ROW_FORCED_SPLIT` 块级提示；
- 表题与至少第一行表格保持同页；
- 表内文字使用直接左、中、右对齐，不继承正文首行缩进。

### 公式

- 公式内容必须优先使用 WPS 原生数学对象；
- 公式居中，编号右对齐；
- 公式和编号保持同页；
- 编号和交叉引用可在字段更新后自动刷新；
- 无边框表格可以作为对齐容器，但不属于数学对象替代品；
- 原生公式运行时失败时，默认保留原始受限 LaTeX 文本并显示原位提示；
  只在用户显式提供有效降级图片时使用该图片。

### 参考文献

- 使用统一悬挂缩进；
- 默认左对齐，避免中英文间距被两端拉伸；
- 引用序号风格由文档配置统一决定；
- 文献条目不得被空段落人为拉开；
- 中英文文献使用一致的段落间距和换行规则。

## 跨平台生成计划

长文档 Writer 使用 generation protocol v2。计划信封固定为：

```json
{
  "protocolVersion": 2,
  "semanticVersion": "longform-1",
  "component": "writer",
  "resourceManifestVersion": 1,
  "resourceManifestDigest": "sha256:<canonical-manifest-digest>",
  "operations": [
    {
      "op": "writer.add_captioned_figure",
      "nodeId": "fig:supplier-network",
      "args": {
        "children": [
          {
            "nodeId": "fig:supplier-network/image:1",
            "resourceId": "image-1"
          }
        ],
        "caption": "供应商网络知识图谱",
        "layout": "stack"
      },
      "failurePolicy": {
        "mode": "degrade",
        "recoverableCodes": ["IMAGE_INSERT_FAILED"],
        "fallback": "notice"
      }
    }
  ]
}
```

`failurePolicy` 只允许 `fail` 或 `degrade`。`degrade` 必须同时声明允许恢复的
稳定错误码和确定性 fallback；未列入白名单的错误一律向上抛出。配置、保存、
字段刷新 API 调用、产物验证和发布类操作只能使用 `fail`。字段 API
成功但在有界轮次内未收敛属于独立的可恢复排版问题，按下述固定规则
输出并标注，不通过 `failurePolicy` 吞掉 API 错误。

共享计划新增以下语义操作：

- `writer.configure_front_matter`
- `writer.configure_section`
- `writer.configure_toc_styles`
- `writer.add_page_break`
- `writer.add_captioned_figure`
- `writer.add_semantic_table`
- `writer.add_equation`
- `writer.add_cross_reference`
- `writer.insert_figure_index`
- `writer.insert_table_index`
- `writer.add_bibliography`
- `writer.add_inline_degradation`
- `writer.add_degradation_notice`
- `writer.add_document_quality_notice`
- `writer.finalize_fields`

`writer.add_captioned_figure` 同时承载单图和首版最多两图的组合；是否并排由
`layout` 和 `columns` 参数决定，不为同一语义另建平台专用操作。
每个 `args.children[]` 必须带稳定子 `nodeId`，并且恰好二选一地带有通过预检的
`resourceId` 或平台无关的 `plannedDegradation`。后者使用已定义的 `code`、
`message`、`fallback` 和 `placement`，不得包含文件路径或伪造资源 ID。
该复合操作的结果必须返回按 `children` 顺序排列的 `childResults[]`，
每项包含子节点 ID、状态、局部错误码和最终定位。一个子图失败时只回滚该
子范围，再按已定义的单图 `stack` 降级组装整体；不得先提交整个组合后
因一个子图失败删除已成功对象。容器、题注或编号结构本身损坏时才回滚
整个顶层范围，然后插入保留题注和引用目标的整体 fallback。

每个操作必须具备：

- 明确的必需字段和可选字段；
- 纯 JSON 参数；
- 严格未知字段拒绝；
- 大小、数量和嵌套深度边界；
- 稳定错误码；
- Windows 和 macOS 等价测试。

完整生成计划状态机固定为：

```text
reset
  -> configure document and styles
  -> configure and render front matter
  -> [configure one section -> render that section's content nodes]*
  -> insert indexes and bibliography
  -> finalize_fields
```

- `reset` 必须唯一且位于首位；
- `configure_section` 必须与对应内容交错出现，不能在文档开头一次性配置所有
  分节；
- 每个语义内容节点 ID 必须在计划中恰好出现一次；复合操作使用顶层
  `nodeId`，批量普通段落使用 `args.segments[]` 记录各子节点；
- 交叉引用目标必须在语义验证阶段已解析为稳定 `nodeId`；
- `finalize_fields` 在每个完整生成计划中必须唯一且位于最后；
- 阶段越界、重复终结或终结后追加内容属于计划无效，不得启动 WPS。

批量段落只是一项性能传输优化，不能丢失子节点定位。执行器必须把每个
segment 还原为独立 WPS 段落范围；第二次生成可以改变批次边界，但不能改变
语义节点 ID。每个 segment 固定包含 `nodeId`、`text`、`normalization` 和
`utf16Length`；普通文本的 `normalization` 必须是 `nfc`，代码节点可以是
`none`。wire offset 和 WPS Range 均使用 UTF-16 code unit，范围使用半开
区间 `[start, end)`，段落间 `\r` 计 1 个 code unit。执行器必须按声明的
normalization 重新计算并核对 `utf16Length`，不接受 Python code point 数
代替 wire 长度。

notice-only patch 使用独立状态机，不执行 `reset`：

```text
open final staged DOCX
  -> patch inline/block/document notices at mapped node ids
  -> finalize_fields
  -> read final pagination_map and refresh issue pages
  -> save
  -> export PDF
```

`finalize_fields` 是“每个执行 pass 恰好一次”，不是整份文档生命周期只能
调用一次。初次生成、唯一一次完整重排和可选 notice-only patch 分别刷新
字段，确保提示引起的分页变化反映到 TOC、图表清单和页码中。

`writer.finalize_fields` 在协议中是一项原子操作，执行器内部必须按以下
固定顺序执行有界收敛：

1. 重新分页，刷新原生标题编号、`SEQ` 题注和公式编号；
2. 刷新书签目标与交叉引用；
3. 刷新目录、图目录和表目录；
4. 再次分页，刷新 `PAGE`、`NUMPAGES` 和分节页码字段；
5. 按 `ownerNodeId + fieldKind + ordinalWithinNode` 的稳定键排序，记录归一化
   字段代码类别、结果哈希、各类目录页数和文档总页数快照。

最多执行 3 轮；相邻两轮快照一致才视为收敛。任一必需原生 API 不存在或
抛错时立即以引擎或能力错误终止；API 均成功但 3 轮后快照仍变化时，
由该原子操作在文档级质量区插入或去重更新 `FIELD_REFRESH_UNSTABLE`
降级提示，再按相同顺序执行一轮最终刷新并冻结该结果。这一特殊分支最多
共 4 轮，不得触发新的外部 notice-only patch。初次生成、完整重排和
notice-only patch 都使用同一收敛算法，不得因 pass 类型不同简化刷新
步骤。字段结果在哈希前统一 NFC 和换行符，但不删除对用户可见的空白；
收敛快照只保存稳定键、哈希、计数和页码，不记录字段可见文本。

### 执行前能力握手

Python 主机在任何 WPS 文档变更之前读取执行器的：

- `protocolVersion`；
- `semanticVersion`；
- 支持的操作目录及其 schema 哈希；
- 资源清单版本及其 schema 哈希；
- 原生能力位，包括多级编号、分节页码、TOC 样式、题注、交叉引用、公式
  和分页定位快照；
- `rangeEncoding: utf16`、`textNormalization: nfc-with-raw-code`、坐标系版本、
  `unicodeDataVersion: 15.1.0`、允许媒体类型和字体能力摘要；
- Windows 额外报告专属实例所有权能力，macOS 额外报告 bridge/add-in 版本。

任一必需值不匹配时抛出 `PROTOCOL_VERSION_MISMATCH` 或
`EXECUTOR_CAPABILITY_MISSING`，不执行 `reset`，也不自动切换 legacy。插件
安装和升级必须把 Python 包、macOS add-in 与能力清单作为一个版本单元。
schema 哈希使用按键排序、无多余空白的 UTF-8 JSON 规范化结果计算 SHA-256，
两个平台不得各自维护不可比较的哈希算法。

### 资源预检与运行期恢复

- 语义规范化阶段先解析资源存在性和可读性，然后从同一已打开的只读文件柄流式
  复制到本次生成专用的私有 staging 目录，同时记录逻辑资源 ID、字节长度和
  SHA-256；
- 类型、大小、可解码性和媒体安全检查只针对该 staging 副本执行。Windows 与
  macOS 都使用该副本，不得让 WPS 在预检后重新打开用户原路径；
- 生成计划的操作参数仍只包含逻辑资源 ID；受控资源清单按键排序、
  无多余空白的 UTF-8 JSON 规范化形式计算 SHA-256，其版本和摘要必须与计划
  信封中的 `resourceManifestVersion` 和 `resourceManifestDigest` 一致。执行器
  通过该清单获得 staging 副本，并在插入前重新核对长度和哈希。清单版本
  或摘要不匹配时以 `RESOURCE_MANIFEST_MISMATCH` 终止，副本不匹配时以
  `STAGED_RESOURCE_CHANGED` 终止；两者都是致命错误，不降级为未知内容；
- 计划中每个逻辑资源 ID 必须在清单中恰好出现一次，清单也不得包含计划未引用的
  额外条目；缺失、重复或多余条目属于 `RESOURCE_MANIFEST_MISMATCH`，必须在
  启动 WPS 之前拒绝；
- 资源 staging 在成功、可恢复降级、致命失败和超时后都必须删除；崩溃遗留
  由下次启动的同版本 janitor 按专用目录标记和最长 24 小时存活期清理。
  允许保留的失败恢复副本只能是已验证的暂存产物，不包含原始资源副本；
- 缺失、类型不支持或预检已确认损坏的资源不进入 `GenerationResource`，而
  根据节点 placement 直接生成行内、块级或文档级降级操作；
- 用户资源不存在或不可读属于局部降级；私有 staging 目录无法创建、
  副本写入中断或哈希计算失败属于 `RESOURCE_STAGING_FAILED` 基础设施级
  致命错误，不得把 staging 磁盘或写入权限故障伪装成单个图片问题；
- 通过预检但在 WPS 插入时失败的资源，由复合操作按白名单错误码执行一次
  fallback 并继续；
- 可恢复操作开始前必须记录顶层插入范围和相关对象计数；复合操作还必须
  为每个可独立降级的子节点记录嵌套 checkpoint。子节点失败时只清理该 checkpoint
  之后产生的局部范围和对象；顶层结构失败时才回滚整个操作。局部或顶层
  恢复验证失败立即升级为 `LOCAL_MUTATION_ROLLBACK_FAILED` 致命错误；
- `writer.add_inline_degradation` 的 fallback 是同一段落内的带方括号纯文本；
- `writer.add_degradation_notice` 的 fallback 是“样式提示框 -> 普通带错误码
  段落”；
- `writer.add_document_quality_notice` 放在固定“生成质量提示”区域，不得插入
  标题、目录字段或页眉页脚内部；
- 上述最简文本 fallback 仍无法写入时视为 Writer 引擎不可用并终止；
- 平台执行器不得捕获所有异常后继续；未知异常、引擎异常和保存异常必须
  终止。

### 执行结果与分页定位

平台执行器内部返回：

```text
ExecutionOutcome
  staged_artifact
  issues[]
  pagination_map[node_id] -> story, sections[], page_start, page_end, range, fragments[]
  fragments[] -> page, bounds|null
  capability_snapshot
```

分页定位必须由 WPS 原生范围、书签或对象锚点产生，并在保存、字段刷新后
重新读取。不允许通过可见文本、隐藏正文哨兵或 PDF 文本猜测 `node_id`。
`range` 对文本节点必需。每个节点至少按其占用的每个物理页返回一个
fragment；纯文本节点在平台无法稳定提供逐页几何信息时允许 `bounds: null`，
但 page 不得为空。图、表和公式等视觉对象的每个 fragment 都必须有 bbox。
单页图片通常只有一个 fragment，跨页表格必须对每页的可见部分分别返回
bbox，不得用一个跨页 bbox 或只记录首页。`page_start` 和
`page_end` 是 fragment 页序的包含式最小/最大值；不适用的字段可以为空。
一次重排后必须重新生成最终 `pagination_map`，旧映射不得复用。

定位协议统一使用：物理页序从 1 开始，与 WPS 导出 PDF 页序一一对应；
可见页码标签单独记录；长度单位为 point；`bounds` 是页面局部的
`[x0, y0, x1, y1]`，原点位于页面左上角；PDF 的 Rotation、MediaBox 和
CropBox 必须先规范化到同一坐标系。文本 `range` 使用节点所声明 normalization
之后文本在整个 WPS 主文档 story 中的 UTF-16 半开区间。页眉、页脚、脚注
等其他 story 必须使用独立 story 标识和局部 range。WPS 快照与 PDF 坐标映射
误差超过 1pt 时不得自动执行位置修复，只能降为低置信度检查结果。

## WPS 原生语义原则

- 标题、目录、页码、题注、交叉引用和公式优先使用 WPS 原生对象或字段。
- 平台 API 可以不同，最终语义和可编辑行为必须一致。
- 不要求 DOCX 字节一致，要求语义快照和 PDF 视觉结果一致。
- 新默认引擎不得依赖新增的 OOXML 变更或后处理；只读解析 OOXML 用于结构
  验证和语义快照是允许的。
- 现有 `numbering_native.py` 在迁移期只服务旧链路。
- 新默认链路通过 WPS 原生列表和标题样式实现编号。
- 旧编号后处理只有在新链路跨平台验收通过后才从默认路径移除。
- 标题和 TOC 样式必须通过内置样式 ID、枚举或经探针验证的稳定标识访问，
  不得只依赖英文或中文显示名称。
- 外部语义 ID 必须映射为合法、确定且无冲突的内部书签名；用户输入不得
  直接成为 WPS 书签或字段代码。

内部书签名固定为 `wpsc_<kind>_<24位SHA256>`，其中 `kind` 只能是受控短码
`fig`、`tab`、`eq`、`ref`、`head` 或 `para`。完整外部 ID 与书签的映射保留
在内部结果中；哈希碰撞按规范化文档顺序追加确定性两位后缀。书签名必须
保持 ASCII 且不超过 40 个字符。

“WPS 原生等价结构”是指由 WPS API 创建、可在 WPS 中继续编辑，并且在
保存、重新打开和字段刷新后仍保持显示内容、更新行为和引用目标的对象或
字段组合。仅视觉相似的静态文本、图片或手写 OOXML 不属于等价结构。
公式布局使用的无边框表格可以是等价布局结构，但表格中的公式内容仍必须
是 Office Math 或 WPS 原生公式对象，才算原生公式能力通过。

## 双平台原生能力可行性门

正式实现前必须分别在真实 Windows WPS 和 macOS WPS 中验证：

1. generation protocol v2 能力握手、资源清单摘要绑定和版本拒绝；
2. Windows 专属 WPS 实例所有权、worker 超时和仅终止自有进程；
3. 字体枚举、逻辑字体映射、实际字体快照和 PDF 字体结果；
4. Unicode 15.1.0 字素簇/`Script=Han`、NFC/原样代码两种 normalization、
   UTF-16 range 与包含 emoji、扩展汉字的批量段落定位；
5. point、左上角原点和 PDF page box 规范化后的坐标映射；
6. `chinese-formal`、`decimal` 和 `hybrid-bid` 的 H1-H4 原生关联多级编号，
   插入、移动、删除、重开后可自动重编号；
7. 原生分页符、分节页码格式、重新起始编号，以及首个、中部和末尾
   横向对象的临时方向节生命周期；
8. TOC 1/2/3 样式修改，且不依赖本地化显示名称；
9. `SEQ` 题注字段、图目录和表目录；
10. 交叉引用字段和安全书签映射；
11. Office Math 或 WPS 原生公式对象，以及无边框布局容器；
12. 单页与跨页节点的
    `node_id -> sections/page_span/range/fragments` 分页定位快照；
13. 可恢复复合操作的嵌套 checkpoint、子节点局部清理、fallback 插入和
    后续操作继续执行；
14. 正常生成与 notice-only patch 中的字段有界收敛、保存和导出；
15. SVG 原生插入、保存和导出；失败则明确排除 SVG，而不是阻断其他格式。

第 1-14 项按适用平台全部必需；其中涉及文档内容的能力还必须验证保存、
关闭、重新打开和字段刷新后的结果。第 15 项是允许媒体类型的可选能力门。
不得转为静态 OOXML 拼补。任一必需能力无法形成跨平台等价语义时不得进入
0.8.0。M0 是明确的 go/no-go 门；必需项未全部通过前不得开始 M1 正式实现。

## 错误与降级模型

### 正常缺省

文档没有图、表、公式、目录或参考文献时，直接按实际内容排版，不产生
提示或 warning。

### 可恢复局部问题

以下问题必须继续生成：

- 已识别布局配置值无效、重复/不支持的前置块内容或非空分页块；
- 标题前缀冲突、编号层级缺失或语义图表题注缺失；
- 已声明图片不存在、损坏或插入失败；
- 公式对象创建失败；
- 表格无法按请求样式排版；
- 引用目标不存在或 ID 冲突；
- 某项高级格式在运行时不可用；
- 图片分辨率或标签尺寸低于质量要求；
- 页眉需要截短，或必需字段 API 均成功但 3 轮后仍未收敛。

处理顺序固定为：

1. 语义或资源预检可以提前确认的问题，直接把原节点规范化为
   对应 placement 的降级节点；
2. 运行期问题先尝试原生排版；
3. 仅对白名单错误执行一次确定性的简化排版；
4. 简化仍失败时，在同一 `node_id` 位置插入行内、块级或文档级提示；
5. 继续后续内容，并将 issue 加入内部 `GenerationOutcome`。

行内降级使用短方括号文本和克制底色；块级降级使用专业的浅黄色或浅灰色
提示框；文档级降级使用统一“生成质量提示”区域。所有可见提示只包含稳定
错误码、对象名称、可读原因和实际降级方式。

信息性 warning 不自动污染文档正文。只有内容缺失、对象不可读、引用不可
解析或排版问题会导致用户误解时，才插入可见提示。首次 PDF 检查发现的
确定性修复进入唯一一次完整重排；最终 PDF 检查仍存在的 degraded 问题只
进入一次 notice-only patch，不再重排正文。

### 引擎级致命问题

以下情况立即终止：

- WPS 未安装、无法启动或 COM/JSAPI 不可用；
- Windows 无法获得或证明专属长文档 WPS 实例所有权；
- generation protocol 或执行器能力不匹配；
- 资源清单版本或摘要不匹配，私有 staging 无法创建或写入，或已校验
  资源副本在执行前发生变化；
- 必需字段刷新或重新分页 API 缺失、抛错或返回无效状态；
- WPS 保存失败；
- 注册恢复失败；
- DOCX 或 PDF 结构无效；
- 内部 PDF 无法导出；
- 必需的 PDF 或图片质量分析组件不可用；
- 原子发布或回滚失败。

致命错误不得启动非 WPS 备用生成器，也不得把不完整文件伪装为成功产物。

## 返回与交付契约

- 公开 `generate()` 继续返回绝对产物路径。
- 内部流水线使用非公开 `_generate_outcome()`，返回
  `GenerationOutcome(path, degraded, issues)`；不承诺第三方兼容。
- `degraded` 问题既进入结构化 issue 列表，也在文档相应位置可见；warning
  和 info 只进入内部结果，不自动写入正文。
- 普通用户不额外收到诊断 JSON。
- 只发布请求的 DOCX 或 PDF。
- 内部 PDF、暂存 DOCX 和资源副本在成功后删除。
- 失败恢复所需的唯一副本按现有原子发布约定保留并报告。

## 质量门

### 生成顺序

1. Markdown 语义验证；
2. 资源预检，并把已知资源问题规范化为降级节点；
3. generation protocol v2 计划闭合验证；
4. 执行器版本和能力握手；
5. WPS 生成暂存 DOCX，并返回 issue 与分页定位快照；
6. 验证标题、字段收敛状态、题注、引用、书签和媒体关系；
7. WPS 临时导出 PDF；
8. 执行页面角色感知的 PDF 质量检查，并映射到 `node_id`；
9. 只有可确定修复的问题才触发唯一一次重排；
10. 重排后重新生成分页定位快照，并执行最终 PDF 质量检查；
11. 最终检查仍存在的 `degraded` 问题只允许执行一次原位置 notice patch，
    patch 内再次执行 `finalize_fields`，随后保存并重新导出 PDF；不得再次
    重排正文；
12. 对 notice patch 后的 DOCX/PDF 执行结构、页面边界和标记存在性验证；
    使用最终分页定位快照更新 issue 页码；新增视觉偏差只记录到同一节点
    issue，不再进入循环；
13. 原子发布请求格式；请求 PDF 时复用最终已验收 PDF，不重复导出；
14. 删除内部证据和暂存文件。

### 确定性检查

- 非预期空白页；
- 页面内容超出正文区域；
- 页眉、页脚、页码格式和序列；
- 标题位于页尾且后续不足两行；
- 图题、表题与对象分离；
- 图片超宽或有效 DPI 过低；
- 表格超宽、表头未重复或非预期行被拆分；已带
  `TABLE_ROW_FORCED_SPLIT` 的超高行只验证可读性和提示存在性，不重复触发重排；
- 目录字号、行距、段间距和末页利用率；
- 题注断号、重复号或交叉引用未解析；
- 字段刷新轮次、相邻快照与收敛状态；
- 参考文献悬挂缩进和异常字符间距；
- 最后一页利用率过低。

质量规则必须识别标题页、摘要、目录、章节首页、正文和参考文献等页面角色。
标题页、显式章节首页和用户显式分页不参与普通正文利用率判断。最后一页
利用率过低默认是 warning，不得删除真实内容。

严重度固定为：

- `fatal`：引擎、协议、保存、结构验证、PDF 导出或发布失败；
- `degraded`：内容对象缺失、不可读、未解析，或一次重排后仍可能误导用户的
  局部排版问题；
- `warning`：可读且不影响语义的质量偏差；
- `info`：自然稀疏页面等无需修复的观察项。

每项 PDF 检查还必须给出 `confidence: high|medium|low` 和可复核 evidence。
结构解析、明确页面边界越界和已映射对象 bbox 可以是 high；依赖文本抽取
顺序或字体启发式的结果最多是 medium；无法获得矢量文字边界的图表标签
判断是 low。只有 high 可以触发重排或自动降级，medium 只能生成 warning，
low 只能生成 info 并进入人工视觉验收清单。

非预期空白页、对象溢出和题注分离先执行一次确定性修复。修复后仍存在时，
只要 DOCX/PDF 结构有效，就按可恢复问题继续输出，并在对应节点或最近的前置
语义节点加入降级说明；不得把视觉问题擅自升级为引擎级致命错误。

### 确定性重排矩阵

- TOC 稀疏溢页：只调整 TOC 1/2/3 样式到已定义最小值；
- 页眉溢出：按同一 Unicode 字素单位算法缩短到不超过 32 个显示单位，
  保持 9pt 和单行，并生成 `HEADER_OVERFLOW` 文档级提示；
- 图片超宽：按正文宽度等比缩小，不自动创建横向节；
- 图片过低：保持可读尺寸并加入提示，不继续缩小掩盖问题；
- 表格超宽：按列宽策略压缩一次；仍超宽则使用节点显式横向节或降级标记；
- 单行或不可分垂直合并组高于可用页面：取消该组垂直合并与禁止跨页规则，
  转为可拆分网格，并在表题后插入 `TABLE_ROW_FORCED_SPLIT` 块级提示；
- 标题孤行：应用 `keep_with_next` 和段落分页规则；
- 题注分离：把对象与题注放入同一原生布局容器或应用保持同页规则。

矩阵之外的问题不允许通过启发式反复调整。每份文档最多执行两次完整 WPS
生成、一次 notice-only patch 和三次 PDF 导出。notice-only patch 只允许在
已映射 `node_id` 处插入提示，不得调整正文样式、对象尺寸或分页策略。

### 人工视觉检查

自动测试不能替代真实 WPS 和 PDF 视觉检查。每个里程碑至少检查代表性的
摘要、目录、正文、图、表、公式、代码、降级标记和参考文献页面。

### 依赖与性能边界

- `pypdf>=4` 和 `pdfplumber>=0.11` 从可选 PDF 编辑依赖提升为 DOCX/PDF
  长文档质量门的核心运行依赖；`reportlab` 仍只服务 PDF 编辑功能；
- `Pillow>=10` 是栅格图片签名、完整解码、像素尺寸、DPI 和 GIF 帧数预检的
  核心运行依赖；
- 缺失必需分析组件时必须在启动 WPS 前失败；
- 公开 `timeout` 覆盖资源预检、两次以内完整生成、一次 notice-only patch、
  三次以内 PDF 导出、验证和发布的完整生命周期，默认仍为 600 秒；
- warning 或 info 不触发第二次生成；只有重排矩阵中的可确定问题才触发；
- 50-100 页验收夹具必须在 Windows 和 macOS 的记录基准机器上于 600 秒内
  完成，验收记录同时保存硬件、WPS 版本、页数、操作数和各阶段耗时；
- 超时后必须恢复 WPS 注册和 ScreenUpdating，清理暂存文件，并且不得发布
  部分产物。

Windows 由主进程监督专属 worker。达到 deadline 后先发送协作取消并给予
最多 5 秒清理窗口；仍未退出时只终止已证明由该 worker 创建的进程树。无法
证明 WPS 进程所有权时不得强杀，且该环境不得通过 M0 硬超时能力门。macOS
继续使用 loopback bridge deadline，并验证注册恢复。两个平台都必须以真实
超时夹具证明不会关闭或修改用户原有的 WPS 窗口和文档。

## 里程碑

### M0：双平台原生能力探针

在 Windows 和 macOS 分别验证上述第 1-14 项必需能力，并评估第 15 项 SVG
可选能力。产出能力矩阵、真实 DOCX/PDF、字体与坐标快照、超时恢复记录和
截图证据，不进入正式 API。

通过标准：每项 0.8.0 能力在 Windows 与 macOS 都有 WPS 原生实现路径，
并通过保存、关闭、重开和字段刷新。任一项失败即暂停 0.8.0 长文档实现，
不得进入 M1。

### M1：长文档语义核心

实现 Markdown 扩展、摘要/关键词/显式分页契约、明确缺省值、语义模型、
资源预检、ID/引用解析、书签
安全映射、NFC/UTF-16 范围、降级 placement、公式子集验证、排版策略和
generation protocol v2 闭合计划。使用 recording composer 验证，不启动
真实 WPS。

通过标准：同一输入稳定生成相同语义计划；缺省内容不报错；声明资源失败
产生降级节点；首章前未编号标题与进入章节后的非法层级跳跃均有稳定语义快照；
计划阶段顺序、节点唯一性、资源清单哈希和失败策略均能在启动 WPS 前验证。

### M2：页面骨架与目录

实现前置页、分节页码、页眉页脚、紧凑目录、标题层级和正文样式。

通过标准：封面不显示页码也不占用罗马序列，无封面文档的标题不丢失；
两个平台真实生成的罗马页码、正文重启、原生标题编号、页眉和目录密度正确，
字段在 3 轮之内收敛，没有意外空白页，并能为标题、目录项和正文节点
返回稳定分页定位。临时横向节不重启正文页码，不产生空节或空白页。

### M3：图、表与交叉引用

实现原生题注、章节式与全局编号、图表清单、三线表、受约束合并、图片格式
策略和交叉引用。

通过标准：移动、插入或删除图表后，WPS 更新字段即可重编号；章节式
图、表、公式分别稳定显示“图 1-1”、“表 1-1”和“(1-1)”，图题和表题
不与对象分离。

### M4：公式、参考文献与降级系统

实现公式编号、公式引用、参考文献样式、引用序号、执行器白名单恢复、行内、
块级和文档级降级提示。

通过标准：数字引用按首次出现编号，重复引用复用编号，未引用条目按配置处理；
所有局部故障和字段不收敛都生成有效且已标注的产物，所有引擎级故障立即终止。

### M5：PDF 质量门与默认迁移

实现内部 PDF、页面角色感知检查、问题到节点映射、一次重排、核心 PDF
分析依赖、性能门、DOCX/PDF 默认行为切换、文档和发布说明。

通过标准：所有真实验收夹具在两个平台通过；DOCX/PDF 的 `generate()` 默认
使用新引擎；PPTX/XLSX 生成计划快照保持不变。

至少维护六类真实夹具：

1. 样例风格的密集学术报告；
2. 含宽图、长表和多章节的技术方案；
3. 含混合原生编号的技术标；
4. 故意缺图、组合图局部失败、题注缺失、非法表格合并、重复前置块、

6. 含 emoji、扩展汉字、混合字体、长页眉和多种图片格式的协议边界文档。

每份夹具在 Windows 和 macOS 上验证：

- DOCX 原生字段和语义快照；
- WPS 打开并执行有界字段刷新后的收敛轮次、快照和结果；
- WPS 导出 PDF 的页面数量和页面边界；
- 封面、无封面标题、原生标题编号和目录收录边界；
- 摘要与关键词的前置位置、重复块的正文保留，以及显式分页不改变分节语义；
- `chinese-formal`、`decimal` 和 `hybrid-bid` 的 H1-H4 可见格式、原生链接
  与重排行为；
- 标题层级跳跃时不生成 `0.1` 类伪编号，且原有标题与 TOC 语义不丢失；
- 页眉、页脚和页码序列；
- 首个、中部和末尾横向对象的方向、节边界、页码连续性和空白页；
- 长页眉的 64/32 显示单位截取边界、emoji 字素完整性和双平台文本一致性；
- 目录密度、孤立标题和空白页；
- 图片 DPI、题注位置和表格跨页；
- 超高单行和垂直合并组的可读拆分与原位降级提示；
- 参考文献首次出现顺序、重复引用复用和未引用条目配置；
- PDF 问题与稳定 `node_id` 的映射，包括跨页表格的逐页 fragment；
- NFC/UTF-16 range、point 坐标和 notice placement；
- 实际字体、字体替代状态和跨平台分页容差；
- 两个平台语义结果一致；
- 代表性页面人工截图检查。

另将第 2 类夹具扩展为 50-100 页性能版本，验证阶段耗时和 600 秒总预算；
短普通 Markdown 不承担长文档性能指标。

另外维护协议不匹配、能力缺失、PDF/Pillow 依赖缺失、Windows 专属实例
不可用、超时恢复和危险公式命令拒绝测试；这些是失败场景，不生成公开验收
文档。

## 兼容性和迁移

- 普通 Markdown 继续可用。
- `generate()` 签名和路径返回值保持兼容。
- 只有 DOCX/PDF 的默认视觉和分页行为升级为新引擎。
- PPTX/XLSX renderer、操作协议和生成计划快照保持现有行为。
- Markdown 扩展成为稳定公共契约。
- 内部 Python 模型不承诺第三方兼容。
- 内置 Unicode 数据版本变更可能改变页眉截取和标题方案检测，必须同时提升
  `semanticVersion`、更新双平台能力握手值并重跑协议边界夹具；
- 提供 `layout_engine: legacy` 迁移开关；它被明确标记为 deprecated，不属于
  稳定长文档语法契约，只用于历史 DOCX/PDF 应急且不接受新能力。
- legacy 在整个 0.8.x 保留，不早于 1.0 移除；移除必须通过主版本迁移说明。
- stale add-in 或协议不匹配属于致命错误，不得被 legacy 自动兜底；只有用户
  在输入中显式声明 legacy 才进入旧链路。

## 版本与发布门

目标版本为 0.8.0。以下条件必须全部满足：

1. M0-M5 全部完成；
2. Windows 与 macOS 使用相同语义版本；
3. 全部平台无关测试通过；
4. Windows 和 macOS 真实 WPS 验收通过；
5. 六类验收夹具全部通过结构与 PDF 质量门；
6. README、SKILL、API 参考和长文档语法文档同步；
7. 插件清单和 Python 包版本一致；
8. Python 主机、Windows 执行器与 macOS add-in 的 protocol v2、资源清单
   版本/schema 和能力清单一致；
9. 默认新引擎和 legacy 逃生路径分别通过验收；
10. PDF 分析核心依赖在全新安装环境可用；
11. Pillow 图片预检和允许媒体类型在全新安装环境可用；
12. Windows 专属 worker 和 macOS bridge 均通过安全超时恢复；
13. 50-100 页性能夹具在两个基准平台满足 600 秒预算；
14. PPTX/XLSX 生成计划回归快照无变化；
15. 无关未跟踪文件、本地锁文件和客户文档不进入提交或发布包。

## 安全和隐私

- 图片和附件只能通过受控资源清单进入计划；
- Windows 和 macOS 资源都必须复制到本次生成的私有 staging，执行器
  只读取已校验副本；
- 诊断信息不得泄露路径、token、环境变量或调用栈；
- 产物继续使用暂存、验证、原子发布和回滚；
- 局部降级不得绕过最终结构验证；
- 不联网获取缺失图片、公式或参考文献；
- 公式解析不得执行宏、文件访问、shell 命令或外部资源加载；
- notice evidence 不得保存客户正文或原始资源路径；
- 不把客户内容写入仓库验收夹具。

## 风险与缓解

### 任一平台 WPS API 缺失

缓解：M0 作为 go/no-go 门先行；允许 WPS 原生等价结构，不允许 OOXML
拼补。无等价能力则不进入 M1，也不进入 0.8.0。

### 主机与 add-in 协议漂移

缓解：执行前比较 protocol version、semantic version、操作 schema 哈希和
必需能力位；不匹配时在 WPS 修改文档前失败；安装器按一个版本单元更新
Python 包和 add-in。

### Windows COM 阻塞或错误连接用户实例

缓解：长文档只在受监督的专属 worker 和已证明所有权的 WPS 实例中执行；
禁止默认链路使用普通 `Dispatch` fallback；超时只终止自有进程树。无法证明
实例所有权即不通过 M0。

### 字体缺失导致分页漂移

缓解：使用逻辑字体角色、WPS 字体枚举和已批准的平台等价矩阵；保存后核对
实际字体和 PDF 字体；未知替代生成文档级提示；用明确页数和章节锚点容差
验收，而不是假设字体名称写入成功。

### Unicode range 或坐标系不一致

缓解：统一 NFC、UTF-16 半开区间、1-based 页码、point 和左上角 page-local
bbox；使用 emoji、扩展汉字、Rotation 和 CropBox 夹具；映射误差超过 1pt 时
禁止自动修复。

### 跨平台字段刷新差异

缓解：比较语义快照和 WPS 导出 PDF，不比较 DOCX 字节；在两个平台分别
按同一顺序执行有界刷新，并比较基于稳定字段键的哈希、计数和页码，不记录
客户可见字段文本。

### 质量门误报

缓解：区分页面角色、fatal、degraded、warning 和 info；重排最多一次；单页
目录不检查 35% 阈值；最后一页低利用率不自动删减内容。

### PDF 分析依赖或性能成本

缓解：把必需分析库提升为核心依赖并在 WPS 启动前检查；warning 不触发
重排；最多两次完整生成、一次 notice-only patch 和三次导出；用 50-100 页
真实夹具记录分阶段耗时。

### 局部降级污染正式交付

缓解：标记使用专业样式、稳定错误码和最少必要信息；用户可定位并替换问题
资源；不以空白或静默丢失掩盖失败。

### 默认行为升级影响历史文档

缓解：0.8.0 发布说明明确行为变化；legacy 开关在整个 0.8.x 保留且不早于
1.0 移除；维护旧输入与新引擎的回归夹具。

### 里程碑范围过大

缓解：M0-M5 各自产生独立、可测试交付物；实施阶段为每个里程碑编写独立
计划和审查门，不使用单一大提交完成全部工作。
